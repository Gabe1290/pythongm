# Match-3 — Уровень 3

Продолжение с ограничением ходов / несколькими уровнями /
специальными плитками для [`match3_2`](../match3_2/README.md),
обещанное в исходной Дорожной карте match3_1 — последняя из трёх
запланированных версий match3. Та же архитектура на протяжении всего:
без скриптов, вся игра по-прежнему состоит из четырёх событий
`execute_code` на едином управляющем объекте, лишь размещённых в трёх
комнатах вместо одной.

**Куда это вписывается:** часть семьи `match3_*` — чистый скрипт
`execute_code`, без встроенных действий, без плиток на уровне
комнаты, завершает прогресс, описанный в
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays).

**Звук и музыка:** 5 звуковых файлов — 3 из `match3_2`
(`snd_swap`/`match`/`cascade`) плюс 2 новых (`snd_special`,
`snd_level_up`), все активно используются через `self._sound_queue`.

## Как играть

Те же правила обмена/совпадения/каскада, что и match3_1 и match3_2, плюс:

- У вас есть **ограниченное количество ходов** на уровень. Ход
  тратится только на обмен, действительно создающий совпадение (`if
  marks: self.moves = self.moves - 1`) — недействительный обмен
  (который сдвигается обратно) можно попробовать снова бесплатно.
- Наберите **целевой счёт** уровня, прежде чем закончатся ходы,
  чтобы перейти к следующей комнате. Закончатся первыми — и уровень
  завершается — **щёлкните где угодно, чтобы повторить попытку** того
  же уровня с начала.
- **Соберите 4 в ряд** (ровно 4), и одна из четырёх плиток становится
  **спецэффектом очистки ряда**: белая полоса отмечает её. Соберите
  её снова позже (как часть любого другого совпадения), и она
  очищает **весь свой ряд или столбец** — в зависимости от того, в
  каком направлении шёл исходный забег из 4.
- **Соберите 5 или более в ряд**, и одна плитка становится
  **спецэффектом цветной бомбы**: белое кольцо отмечает её. Соберите
  её снова позже, и она очищает **каждую плитку одного цвета** по
  всей доске.
- Существуют **3 уровня**, каждый со своей комнатой с более высокой
  целью и более жёстким ограничением ходов. Пройдите уровень 3, чтобы
  победить в игре.

## Чем отличается от match3_2

| match3_2 | match3_3 |
| -------- | -------- |
| Одна комната, неограниченные ходы, победа при фиксированном счёте | **3 комнаты** (одна на уровень), **ограничение ходов** на уровень, и **растущая цель** на уровень |
| Совпадение всегда полностью уничтожается | Забег **4** или **5+** оставляет после себя **специальную плитку** вместо уничтожения каждой клетки |
| Нет перехода между уровнями | Достижение цели вызывает `self.advance_level()`, который устанавливает `self.goto_room_target` на следующую комнату (или `self.won` на последнем уровне) |

Основной конечный автомат обмена/мигания/падения/каскада, рисование
плиток спрайтами и триггеры очереди звуков иначе не изменены по
сравнению с match3_2 — полное описание `swap_off`/`falling`/
`find_matches` см. в README того образца.

## Структура проекта

| Файл | Назначение |
| ---- | ------- |
| `project.json` | манифест проекта — окно 800×800, 60 кадров/с, стартовая комната `rm_level1`, `room_order` = все 3 уровня |
| `rooms/rm_level1\|2\|3.json` | одна комната на уровень, каждая содержит свой собственный экземпляр `obj_GridManager` в координатах (0, 0) |
| `objects/obj_GridManager.json` | вся игра: четыре события, каждое с одним действием `execute_code` |
| `sprites/`, `sounds/` | плитки самоцветов + эффекты, в основном скопированы из match3_2 (см. `CREDITS.txt`); `snd_special` и `snd_level_up` новые |

По-прежнему нет объекта на каждую плитку и нет скриптов — один
управляющий экземпляр на комнату, создаваемый заново (по обычному
правилу GameMaker "каждая комната имеет свои собственные экземпляры")
каждый раз при входе в комнату, что бесплатно даёт каждому уровню
чистый старт.

## Как работает код

### Настройка уровня (новое в `create`)

```python
self.room_order = ['rm_level1', 'rm_level2', 'rm_level3']
level_config = {
    'rm_level1': (300, 20),   # (целевой счёт, ограничение ходов)
    'rm_level2': (500, 18),
    'rm_level3': (800, 16),
}
```

`create` читает `game.current_room.name`, сохраняет это в
`self.room_name` (необходимо, поскольку обычная локальная переменная,
определённая в одном событии `execute_code`, **не** выживает до
более позднего события — см. примечание о ловушке ниже), и
устанавливает `self.target`/`self.moves`/`self.level_num` из
приведённой выше таблицы.

### Ходы и поражение (новое в `mouse_left_press`)

Обмен потребляет ход только если `find_matches` говорит, что он
действительно даст совпадение (`if marks: self.moves = self.moves -
1`), поэтому отклонённый обмен, сдвигающийся обратно, бесплатен.
Когда `self.moves` достигает 0 без достижения цели, `step`
устанавливает `self.lost = True`; `mouse_left_press` проверяет этот
флаг **первым**, перед обычной проверкой ввода, и превращает любой
щелчок в `self.restart_room_flag = True` (тот же флаг, который
использует `restart_room`), что перестраивает комнату — а с ней и
свежий экземпляр `obj_GridManager`, чьё событие `create` всё
сбрасывает.

### Специальные плитки (новое в `step`)

`find_matches` теперь возвращает `(marks, runs)` вместо просто
`marks` — каждый забег — это `(cells_in_order, 'h' или 'v')`. При
истечении мигания, **перед** подсчётом очков:

1. Для каждого забега длиной ≥ 4 **средняя клетка** становится
   специальной плиткой вместо уничтожения: забеги длиной 4 получают
   `('row',)` или `('col',)` (в соответствии с ориентацией забега);
   забеги длиной 5+ получают `('color', <индекс цвета>)`.
2. Для каждой уже отмеченной клетки, имеющей запись в `self.special`
   (то есть специальная плитка только что попала в *это*
   совпадение), её эффект срабатывает один раз: спецэффект
   `row`/`col` добавляет весь свой ряд/столбец к клеткам, которые
   очищаются; спецэффект `color` добавляет каждую клетку на доске
   своего сохранённого цвета. Это **единственный, нерекурсивный
   проход** — если взрыв одной специальной плитки охватывает другую
   специальную плитку, та уничтожается, но **не** запускает цепочкой
   свой собственный эффект. (Упрощение, а не ошибка — сохраняет
   эффект ограниченным и лёгким для понимания.)
3. Только что созданные специальные клетки защищены от уничтожения в
   той же волне, даже если бы взрыв из шага 2 их захватил.
4. `self.special` перестраивается с нуля каждую волну, следуя за
   выжившими плитками, когда они падают (цикл падения по столбцу
   теперь несёт третий элемент кортежа — специальный вид плитки, или
   `None` — наряду с её рядом и цветом), поэтому специальная плитка,
   которая ещё не была сопоставлена, сдвигается вниз под действием
   гравитации, как и всё остальное.

### Переход уровня (новое в `create`, используется из `step`)

```python
def advance_level():
    idx = self.room_order.index(self.room_name)
    if idx + 1 < len(self.room_order):
        self.goto_room_target = self.room_order[idx + 1]
        self._sound_queue.append('snd_level_up')
    else:
        self.won = True
self.advance_level = advance_level
```

`self.goto_room_target` — тот же флаг экземпляра, который
устанавливает встроенное действие `goto_room` — главный цикл игры
уже опрашивает его каждый кадр, поэтому установка его напрямую из
`execute_code` достаточна, чтобы вызвать настоящий переход комнаты,
без необходимости в структурированном действии. `step` вызывает
`self.advance_level()`, как только `self.score >= self.target`, и
пропускает любое повторное сканирование каскада на оставшуюся часть
этого кадра, если теперь ожидает смена комнаты (или финальная
победа), поэтому покидаемая комната не продолжает анимироваться.

### Ловушка: замыкания над обычными локальными переменными не выживают между событиями

Среда выполнения `execute_code` передаёт **отдельные** словари
глобальных и локальных переменных (`exec(code, exec_globals,
exec_locals)`), что означает, что она ведёт себя как внутри функции:
обычное присваивание на верхнем уровне (`room_name = ...`) попадает в
словарь *локальных* переменных, но `def`, определённый на том же
верхнем уровне, разрешает свои свободные переменные через словарь
*глобальных* переменных, когда его позже **вызывают** — что для
вложенного помощника, сохранённого на `self` (как `find_matches`,
`arm_swap`, и теперь `advance_level`), всегда происходит из
**другого** вызова `execute_code` с собственным свежим словарём
локальных переменных. Голая локальная переменная, на которую
ссылается такой помощник, вызывает `NameError` при первом фактическом
вызове помощника из другого события — она выглядит нормально в
событии определения и молча ломается, пока не сработает позже.
Исправление — то же, что `find_matches` из match3_1/`arm_swap` из
match3_2 уже смоделировали, не сказав этого явно: замыкайтесь только
над `self` (всегда присутствует в глобальных переменных каждого
события) или **атрибутами экземпляра** (`self.room_name`, а не
голая `room_name`) — никогда над голой локальной переменной.
Обнаружено отдельным шагом проверки с автономной средой во время
разработки (см. примечания о методологии аудита в репозиторном
`CLAUDE.md`); теперь для этого существует регрессионный тест
(`tests/test_match3_3_sample.py`).

### `draw`

Тот же рисунок панели/доски/выбора/строки очков/баннера победы, что и
match3_2, плюс: строка HUD для номера уровня и оставшихся ходов,
наложенная белая полоса или кольцо поверх спрайта специальной плитки
(пропускается, пока плитка посреди мигания), и баннер "OUT OF MOVES
— click to retry", когда `self.lost`.

### Что можно настроить

- Сложность по уровню: таблица `level_config` в `create` (целевой
  счёт, ограничение ходов) — добавьте четвёртую запись и четвёртую
  комнату, чтобы расширить последовательность.
- Радиус взрыва специальной плитки: ветви `row`/`col`/`color` в
  цикле активации в `step`.
- Всё, что match3_2 уже открыл (размер доски, скорость
  обмена/падения, громкость звука).

## Дорожная карта

Это завершает исходную трёхчастную дорожную карту match3_1 (match3_1
→ match3_2 → match3_3). Дальнейших запланированных версий нет.

## Статус экспорта

- **Test Game (F5) / настольный:** работает — проверено сквозным
  образом с настоящим прогоном `GameRunner`, вставляющим фактический
  клик мыши через стандартный путь событий pygame: принудительное
  совпадение 4-в-ряд → создана специальная плитка → достигнута цель
  → **комната действительно переключилась на `rm_level2`** со свежим
  экземпляром (`level_num == 2`, сброшены счёт/ходы).
- **Android (.apk) / мобильный (Kivy):** полагается на тот же
  механизм `asset_paths.py` / `_drain_sound_queue` / резервного
  разрешения спрайта по имени, который добавил и проверил match3_2 —
  этот образец не проверяет ничего нового в этой области (без новых
  типов команд отрисовки, без новых типов действий; `goto_room` через
  флаг работает идентично в экспортированном цикле сцены Kivy,
  который уже опрашивает те же флаги экземпляра каждый кадр). Для
  фактической сборки `.apk` дополнительно требуется buildozer (через
  WSL на Windows) — см. [`docs/ANDROID_EXPORT.md`](../../docs/ANDROID_EXPORT.md).
- **Веб (HTML5):** та же логика — никаких новых примитивов очереди
  отрисовки или очереди звуков сверх того, что match3_2 уже доказал
  на этой цели.
- **Автономный zip:** не проверено с этим образцом.
