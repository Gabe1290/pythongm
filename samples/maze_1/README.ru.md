# Лабиринт — Уровень 1

Игра-лабиринт в сетке с видом сверху: проведите спрайт игрока через
лабиринт, ограниченный стенами, чтобы достичь целевой плитки, что
переводит к следующей комнате. Это родной проект pygm2 (без
сопутствующего файла `.gmk` — его ресурсы изначально были принесены
через импорт GameMaker 8.x, согласно CREDITS.txt, но сам проект
написан/сохранён в собственном формате JSON pygm2).

**Куда это вписывается:** `maze_*` — первая из трёх семей образцов в
грубой прогрессии техники авторства (встроенные объекты/спрайты →
`plateforme_*`, добавляющая тайловые фоны → игры `match3_*` на
чистом скрипте `execute_code`) — см.
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays)
для полной картины. Этот образец использует только GameObjects +
спрайты, без фонового изображения и без плиток на уровне комнаты.

**Звук и музыка:** отсутствуют — ни одного звукового файла не
добавлено к этому образцу.

## Как играть

- **Клавиши со стрелками** (вверх/вниз/влево/вправо) перемещают
  игрока на одну клетку сетки (32px) за раз; движение привязано к
  сетке через `test_alignment`/`snap_to_grid` (сетка 32×32).
- Стены (`obj_wall`) твёрдые — врезание в них останавливает игрока и
  повторно выравнивает его по сетке.
- **Цель:** достичь целевой плитки (`obj_goal`). Касание её переводит
  к следующей комнате, если она существует, или перезапускает игру,
  если её нет.
- **Клавиши отладки:** нажатие `N` на цели переходит к следующей
  комнате (если есть); нажатие `P` переходит к предыдущей комнате
  (если есть) — та же логика перехода/перезапуска, что и касание цели.
- В этом образце не используется отслеживание жизней/очков/здоровья
  (здоровье сбрасывается через `set_health` при переходе комнаты, но
  никогда не отображается).

## Структура проекта

| Файл | Назначение |
|---|---|
| `project.json` | Манифест проекта — настройки окна/комнаты и встроенные копии всех ресурсов |
| `rooms/room0.json` | Макет лабиринта для комнаты 0 (131 экземпляр: стены, старт игрока, цель) |
| `rooms/room1.json` | Макет лабиринта для комнаты 1 (130 экземпляров) |
| `objects/obj_person.json` | Определение объекта игрока (источник истины; соответствует встроенной копии в `project.json`) |
| `objects/obj_goal.json` | Определение целевого объекта |
| `objects/obj_wall.json` | Определение объекта стены |
| `sprites/` | `spr_person.png`, `spr_wall.png`, `spr_goal.png` + их метаданные `.json` |
| `CREDITS.txt` | Уведомление о лицензировании ресурсов для этого образца |

Боковые файлы `objects/*.json` были проверены относительно встроенных
копий `project.json` и идентичны в этом образце — устаревания не
обнаружено.

## Объекты

| Объект | Роль | Ключевые события |
|---|---|---|
| `obj_person` | Персонаж, управляемый игроком; движение на основе сетки | неявно через клавиатуру, keyboard (down, right, up, left, nokey), collision_with_obj_wall |
| `obj_goal` | Выход уровня; переходит/перезапускает при касании или клавише отладки | collision_with_obj_person, keyboard_press (p, n) |
| `obj_wall` | Статичная твёрдая стена лабиринта, блокирует движение | (нет — только пассивный коллайдер) |

## Ресурсы

3 спрайта (`spr_person`, `spr_wall`, `spr_goal`, каждый 32×32, один
кадр, точное до пикселя столкновение), 0 звуков. Лицензирование:
`spr_person.png` и `spr_wall.png` — работы CC0 (общественное
достояние) автора pygm2; происхождение `spr_goal.png` ещё не
задокументировано — см. `CREDITS.txt` в этой папке и
`docs/ASSET_LICENSES.md` в корне репозитория для полной картины.

## Что можно настроить

- Скорость движения игрока составляет `4` (клетки сетки/шаг), тогда
  как остановка при столкновении со стеной использует скорость `8` —
  оба жёстко закодированных параметра действия на нажатие клавиши в
  `obj_person`.
- Размер сетки составляет `32` (соответствует спрайтам 32×32);
  изменение требует соответствующих правок в вызовах
  `snap_to_grid`/`test_alignment` и макетах комнат.
- Комнаты имеют размер `480×480` при `room_speed: 30` — маленькие
  лабиринты с одним экраном, без прокрутки.
- Клавиши отладки `N`/`P` на `obj_goal` позволяют перепрыгивать
  между room0/room1, не касаясь цели — удобно для тестирования, но
  легко случайно нажать во время игры.

Покрыто набором безголовых smoke-тестов
(`tools/smoke_run_samples.py`, который перечисляет `maze_1` и

отдельно не проверено для каждой цели экспорта (Kivy/веб).
Выставлено на вкладке Welcome редактора как "Maze — Level 1"
(`widgets/welcome_tab.py`).
