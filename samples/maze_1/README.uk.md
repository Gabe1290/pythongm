# Лабіринт — Рівень 1

Гра-лабіринт у сітці з видом зверху: проведіть спрайт гравця через
лабіринт, обмежений стінами, щоб досягти цільової плитки, що
переводить до наступної кімнати. Це рідний проєкт pygm2 (без
супутнього файлу `.gmk` — його ресурси були спочатку принесені через
імпорт GameMaker 8.x, згідно з CREDITS.txt, але сам проєкт
написаний/збережений у власному форматі JSON pygm2).

**Куди це вписується:** `maze_*` — перша з трьох родин зразків у
грубій прогресії техніки авторства (вбудовані об'єкти/спрайти →
`plateforme_*`, що додає тайлові фони → ігри `match3_*` на чистому
скрипті `execute_code`) — див.
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays)
для повної картини. Цей зразок використовує лише GameObjects +
спрайти, без фонового зображення й без плиток на рівні кімнати.

**Звук і музика:** відсутні — жодного звукового файлу не додано до цього зразка.

## Як грати

- **Клавіші зі стрілками** (вгору/вниз/ліворуч/праворуч) переміщують
  гравця на одну клітинку сітки (32px) за раз; рух прив'язаний до
  сітки через `test_alignment`/`snap_to_grid` (сітка 32×32).
- Стіни (`obj_wall`) тверді — врізання в них зупиняє гравця й
  повторно вирівнює його до сітки.
- **Мета:** досягти цільової плитки (`obj_goal`). Дотик до неї
  переводить до наступної кімнати, якщо вона існує, або перезапускає
  гру, якщо її немає.
- **Клавіші налагодження:** натискання `N` на цілі переходить до
  наступної кімнати (якщо є); натискання `P` переходить до попередньої
  кімнати (якщо є) — та сама логіка переходу/перезапуску, що й дотик
  до цілі.
- У цьому зразку не використовується відстеження життів/очок/здоров'я
  (здоров'я скидається через `set_health` при переході кімнати, але
  ніколи не відображається).

## Структура проєкту

| Файл | Призначення |
|---|---|
| `project.json` | Маніфест проєкту — налаштування вікна/кімнати й вбудовані копії всіх ресурсів |
| `rooms/room0.json` | Макет лабіринту для кімнати 0 (131 екземпляр: стіни, старт гравця, ціль) |
| `rooms/room1.json` | Макет лабіринту для кімнати 1 (130 екземплярів) |
| `objects/obj_person.json` | Визначення об'єкта гравця (джерело істини; відповідає вбудованій копії в `project.json`) |
| `objects/obj_goal.json` | Визначення цільового об'єкта |
| `objects/obj_wall.json` | Визначення об'єкта стіни |
| `sprites/` | `spr_person.png`, `spr_wall.png`, `spr_goal.png` + їхні метадані `.json` |
| `CREDITS.txt` | Повідомлення про ліцензування ресурсів для цього зразка |

Бічні файли `objects/*.json` були перевірені відносно вбудованих
копій `project.json` і є ідентичними в цьому зразку — застарілості не
виявлено.

## Об'єкти

| Об'єкт | Роль | Ключові події |
|---|---|---|
| `obj_person` | Персонаж, керований гравцем; рух на основі сітки | неявно через клавіатуру, keyboard (down, right, up, left, nokey), collision_with_obj_wall |
| `obj_goal` | Вихід рівня; переходить/перезапускає при дотику або клавіші налагодження | collision_with_obj_person, keyboard_press (p, n) |
| `obj_wall` | Статична тверда стіна лабіринту, блокує рух | (немає — лише пасивний колайдер) |

## Ресурси

3 спрайти (`spr_person`, `spr_wall`, `spr_goal`, кожен 32×32, один
кадр, точне до пікселя зіткнення), 0 звуків. Ліцензування:
`spr_person.png` і `spr_wall.png` — роботи CC0 (суспільне надбання)
автора pygm2; походження `spr_goal.png` ще не задокументовано —
див. `CREDITS.txt` у цій папці та `docs/ASSET_LICENSES.md` у корені
репозиторію для повної картини.

## Що можна налаштувати

- Швидкість руху гравця становить `4` (клітинки сітки/крок), тоді як
  зупинка при зіткненні зі стіною використовує швидкість `8` — обидва
  жорстко закодовані параметри дії на натискання клавіші в
  `obj_person`.
- Розмір сітки становить `32` (відповідає спрайтам 32×32); зміна
  вимагає відповідних правок у викликах `snap_to_grid`/`test_alignment`
  і макетах кімнат.
- Кімнати мають розмір `480×480` при `room_speed: 30` — маленькі
  лабіринти з одним екраном, без прокрутки.
- Клавіші налагодження `N`/`P` на `obj_goal` дозволяють перестрибувати
  між room0/room1, не торкаючись цілі — зручно для тестування, але
  легко випадково натиснути під час гри.

## Статус експорту

Покрито набором безголових smoke-тестів
(`tools/smoke_run_samples.py`, який перелічує `maze_1` і запускає
його на ~180 кадрів із вбудованим введенням клавіатури); окремо не
перевірено для кожної цілі експорту (Kivy/веб). Виставлено на вкладці
Welcome редактора як "Maze — Level 1" (`widgets/welcome_tab.py`).
