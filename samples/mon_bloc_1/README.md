# My Blocks — Lesson 1

A tiny coin-collecting game whose real point is not the game itself, but
the lesson baked into its code: **"My Blocks"**, Blockly's feature for
defining your own custom block (docs/BLOCKLY_SCRATCH_PARITY_PLAN.md
Feature 2, in this project's dev docs). This is a native pygm2 project,
authored directly in the IDE (no `.gmk` import, no `execute_code`) —
everything here is built from ordinary built-in action blocks.

**Sound & music:** none — no sound files are bundled with this sample.

## How to play

- **Arrow keys** (up/down/left/right) move the player one grid cell
  (32px) at a time.
- Walk into a coin to collect it: **bronze** coins are worth 5 points,
  **silver** coins 10, **gold** coins 25. The score is shown top-left.
- There's no wall, no goal, no win condition — just three kinds of coin
  to collect while you look at how the game is built (see below).

## The lesson: notice the repetition, then remove it

Open `obj_joueur` in the Object Editor and switch to its **Blockly**
tab. You'll see three collision events — one for each coin colour — and
each one does *exactly the same two things*, with only one number
different:

| Event | Action 1 | Action 2 |
|---|---|---|
| `collision_with_obj_piece_bronze` | Destroy other instance | Add to score: **5** |
| `collision_with_obj_piece_argent` | Destroy other instance | Add to score: **10** |
| `collision_with_obj_piece_or` | Destroy other instance | Add to score: **25** |

That's the pattern every programmer learns to spot: when you catch
yourself copying the same few blocks over and over and only changing one
value, it's time to turn them into **your own block** instead. Here's
how, step by step:

1. Open the **My Blocks** category at the bottom of the Blockly toolbox
   (it's always there, even though it starts empty) and click **Make a
   Block**.
2. Name it `donner_points` and add one input — click the blue **+** on
   the mutator dialog, name the new parameter `montant` ("amount"), and
   close the dialog.
3. You now have a new "define donner_points (montant)" block on the
   canvas. Drag **"Destroy other instance"** and **"Add to score"**
   into it — the same two blocks you saw repeated three times above.
4. Drag the `montant` parameter (it appears as a little puzzle piece on
   the "define" block itself, the same shape the "Set Variable" block
   uses for its own value) into "Add to score"'s number slot, replacing
   the `5`/`10`/`25` you'd otherwise have to type three times.
5. Go back to the three collision events. In each one, delete the
   "Destroy other instance" + "Add to score" pair and replace it with a
   single **call `donner_points`** block (also in the My Blocks
   category) — typing `5` for bronze, `10` for silver, `25` for gold in
   its one input socket.

The game plays exactly the same afterward — but now the "what happens
when you collect a coin" logic exists in exactly **one** place, so
fixing a bug in it (or adding a fourth action, like a sound) only ever
needs to happen once.

**Want to go further?** A custom block can also *return a value*
instead of just running actions — in the "Make a Block" dialog, tick
"with output" when creating one, and plug a plain arithmetic expression
into its `return` slot (no actions, just a calculation). That kind of
block can be dropped straight into a number socket elsewhere, the same
way `donner_points` here is called as a statement. This sample doesn't
use one — the lesson above is deliberately kept to the simpler,
action-running kind of block first.

## Project structure

| File | Purpose |
|---|---|
| `project.json` | Project manifest — window/room settings and embedded copies of all assets |
| `rooms/room0.json` | The one room: player start + 2 of each coin colour |
| `objects/obj_joueur.json` | Player object — grid movement + the three repeated collision events this lesson is about |
| `objects/obj_piece_bronze.json`, `obj_piece_argent.json`, `obj_piece_or.json` | The three coin types — purely passive; `obj_joueur` does all the work on collision |
| `objects/obj_hud.json` | Invisible controller object that draws the score |
| `sprites/` | `spr_joueur.png` + three coin sprites, generated by `tools/gen_mon_bloc_1_sprites.py` |
| `CREDITS.txt` | Asset licensing notice for this sample |

## Objects

| Object | Role | Key events |
|---|---|---|
| `obj_joueur` | Player-controlled character; grid-based movement, collects coins | keyboard (up, down, left, right, nokey), collision_with_obj_piece_bronze/argent/or |
| `obj_piece_bronze` / `obj_piece_argent` / `obj_piece_or` | Collectible coin, worth 5/10/25 points | (none — passive, destroyed by the player's own collision handler) |
| `obj_hud` | Invisible; draws the running score | draw |

## Assets

4 sprites (`spr_joueur` 24×24, three coin sprites 16×16, all single-frame),
0 sounds. All of them are flat-colour placeholder shapes generated by
`tools/gen_mon_bloc_1_sprites.py`, dedicated to the public domain (CC0) —
see `CREDITS.txt`.

## Export status

Covered by the headless smoke-test suite (`tools/smoke_run_samples.py`,
which lists `mon_bloc_1`); not individually re-verified per export
target (HTML5/Kivy) — the gameplay itself uses only long-established,
already-covered actions (`set_score`, `destroy_instance`, grid movement,
`draw_score`), so there is nothing export-target-specific about this
sample. Exposed in the IDE's Welcome tab as "My Blocks — Lesson 1"
(`widgets/welcome_tab.py`). **Not covered on purpose**: the "My Blocks"
feature itself is Blockly-authoring-time-only (docs/
BLOCKLY_SCRATCH_PARITY_PLAN.md) — a custom block is expanded away into
ordinary actions before it's ever saved, so there is nothing for an
export target to support either way.
