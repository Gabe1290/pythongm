# Match-3 — Рівень 1

Мінімальна, повна головоломка «три в ряд» (match-3). Це перший
зразок pygm2, **написаний безпосередньо у власному форматі проєкту
редактора** — зразки лабіринту та платформера були імпортовані з
файлів GameMaker 8.x `.gmk`; цей був написаний безпосередньо для
середовища виконання pygm2.

Він навмисно малий: одна кімната, один об'єкт, без скриптів, без
звуків. Уся гра міститься у чотирьох подіях єдиного контрольного
об'єкта, що робить його еталонним зразком для дії `execute_code` та
для рендерингу через чергу малювання (draw queue). Складніші версії
(плитки на основі спрайтів, звук, рівні) заплановані як `match3_2`
тощо — див. *Дорожню карту* нижче.

**Куди це вписується:** `match3_*` — остання (і найбільш відмінна) з
трьох родин зразків — інша парадигма, а не поступовий крок: без
вбудованих дій, без об'єктів на кожну плитку, без плиток на рівні
кімнати. Усе (стан сітки, зіткнення, рендеринг) керується
безпосередньо з Python-коду `execute_code`, а не складається з
вбудованих дій через багато об'єктів, як це роблять `maze_*` та
`plateforme_*`. Див.
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays)
для повного прогресу.

**Звук і музика:** відсутні — навмисно, згідно з абзацом вище. (Звук
стає можливим починаючи з `match3_2`, через примітив черги звуків,
який запровадив той зразок.)

## Як грати

- **Клацніть** плитку, щоб вибрати її (білий контур), потім
  **клацніть сусідню плитку**, щоб поміняти їх місцями.
- Якщо обмін вирівнює **3 або більше плиток однакового кольору** в
  ряд або стовпець, збіжні плитки на мить блимають, знищуються, а
  плитки над ними **зсуваються вниз**, щоб заповнити прогалину; нові
  плитки падають зверху дошки.
- Ланцюгові реакції ("каскади") розв'язуються хвилями, кожна зі своєю
  анімацією блимання й зсуву.
- Обмін, що не створює збігу, негайно скасовується.
- Кожна знищена плитка коштує **10 очок**; досягніть **500 очок**,
  щоб перемогти.

## Структура проєкту

| Файл | Призначення |
| ---- | ------- |
| `project.json` | маніфест проєкту — вікно 800×800, 60 кадрів/с (`room_speed`), стартова кімната `rm_match3` |
| `rooms/rm_match3.json` | єдина кімната; містить один екземпляр `obj_GridManager` за координатами (0, 0) |
| `objects/obj_GridManager.json` | уся гра: чотири події, кожна з однією дією `execute_code` |
| `sprites/spr_red|blue|green|yellow.*` | квадрати плиток 32×32 — **поки не використовуються**; зарезервовані для наступної версії на основі спрайтів (див. `CREDITS.txt`) |

Немає об'єкта гравця й немає об'єкта на кожну плитку: дошка — це
чисті дані (список кольорових індексів 6×6), що належать одному
невидимому контрольному екземпляру, і все на екрані малює подія
`draw` цього контролера через чергу малювання середовища виконання
(`self._draw_queue`).

## Як працює код

Увесь стан живе на контрольному екземплярі (`self.…`), створений у
події `create`:

| Атрибут | Значення |
| --------- | ------- |
| `grid` | список 6×6 цілих чисел 0–3 (індекси в `palette`); засіяно без наявних збігів |
| `sel` | наразі вибрана клітинка `(gx, gy)` або `None` |
| `marked` | набір клітинок, що наразі збігаються й блимають |
| `flash` / `flash_total` | кадри, що залишилися у фазі блимання / її тривалість (36 кадрів ≈ 0,6 с при 60 кадрах/с) |
| `falling` | словник `(gx, gy) → пікселі` — наскільки над своєю клітинкою спочинку зараз знаходиться кожна плитка, що зсувається |
| `fall_speed` | швидкість зсуву в пікселях за кадр (12 → один ряд 96 px за ~0,13 с) |
| `score`, `target`, `won` | стан рахунку (перемога при 500) |
| `find_matches` | допоміжна функція (визначена в `create`, збережена на екземплярі), що сканує сітку й повертає набір усіх збіжних клітинок |

Гра — невеликий скінченний автомат, керований подією `step`:

```
idle ──(кліки міняють місцями, збіг знайдено)──▶ FLASH (позначені блимають, 36 кадрів)
                                        │ плитки знищено, очки додано
                                        ▼
                                      FALL (зсуви зменшуються на 12 px/кадр)
                                        │ приземлення → повторне сканування сітки
                             новий збіг ─┴─ без збігу
                                 │            │
                                 ▼            ▼
                               FLASH        idle
```

- **`create`** — будує початкову сітку (перекидає будь-яку плитку, що
  створила б негайний збіг), ініціалізує наведений вище стан і
  визначає `find_matches`.
- **`mouse_left_press`** — логіка вибору/скасування вибору; при
  сусідньому обміні застосовує його й або запускає блимання
  (`marked`, `flash`), або скасовує. Введення ігнорується, поки
  триває блимання чи падіння, і після перемоги в грі.
- **`step`** — відраховує блимання; після завершення зараховує очки,
  переписує кожен зачеплений стовпець на його кінцевий макет і
  записує зсув у пікселях у `falling` для кожної плитки, що
  перемістилася (плитки, що вижили, отримують `rows_dropped × 96`;
  плитки поповнення входять зверху дошки). Поки `falling` не порожній,
  кожен зсув зменшується на `fall_speed`; коли все приземлилося,
  повторно сканується на предмет каскадних збігів і або повторно
  запускає блимання, або повертається до idle.
- **`draw`** — малює панель дошки, потім кожну плитку на
  `позиція_спокою − зсув_падіння`. Плитки над верхнім краєм дошки
  обрізаються (частково з'явилися) або пропускаються (повністю
  приховані), тому поповнення виглядає так, ніби зсуваються з-під
  заголовка. Позначені плитки блимають білим кожні 6 кадрів і несуть
  білий контур; вибір, рядок очок, інструкції та банер перемоги
  малюються останніми.

### Що можна налаштувати

- Розмір дошки: `self.cols` / `self.rows` (константи макета `ox`,
  `oy`, `tile` керують розміщенням — дошка 6×6 з плитками 96 px
  вписується у вікно 800×800).
- Кольори / види плиток: `self.palette` (додайте кортеж, щоб отримати
  5-й колір; логіка перекидання й рендерер підхоплюють це
  автоматично, але оновіть `random.randrange(4)` у `create` та `step`).
- Складність: `self.target` (очки для перемоги), `flash_total`,
  `fall_speed`.

## Дорожня карта (заплановані просунуті версії)

- **[match3_2](../match3_2/README.md)** — зроблено: малює плитки за
  допомогою спрайтів замість кольорових прямокутників, додає звукові
  ефекти для обміну/збігу/каскаду та анімацію зсуву при обміні.
- **[match3_3](../match3_3/README.md)** — зроблено: обмеження ходів,
  три кімнати як рівні з підвищенням цілі, та спеціальні плитки зі
  збігів 4/5-в-ряд. Завершує цю дорожню карту.

Версії покликані віддзеркалювати прогресію maze_1→3: кожна є
читабельною різницею відносно попередньої.

## Статус експорту

- **Test Game (F5) / настільний:** працює — гра запускається на
  стандартному середовищі виконання pygame. Перевіряється без
  графічного інтерфейсу в CI-подібних прогонах через
  `tools/smoke_run_samples.py`.
- **Android (.apk) / мобільний (Kivy):** **підтримується** (з
  03.07.2026). Експортоване середовище виконання Kivy рендерить чергу
  малювання гри (прямокутники й текст, з віссю y, перетвореною в
  систему координат Kivy знизу вгору), надсилає торкання як подію
  `mouse_left_press` з координатами кімнати `mouse_x`/`mouse_y` як на
  Android (інвертуючи трансформацію повноекранного масштабування),
  так і на настільному Kivy, і — оскільки ця гра не має подій
  клавіатури — пропускає накладання віртуального D-pad, яке інакше
  закривало б нижній правий кут дошки. Експортована гра перевіряється
  без графічного інтерфейсу в
  `tests/test_kivy_draw_queue_mouse_export.py`, який програє повний
  раунд обмін → блимання → зсув через згенерований код. Для
  фактичної збірки `.apk` додатково потрібен buildozer (через WSL на
  Windows) — див. [`docs/ANDROID_EXPORT.md`](../../docs/ANDROID_EXPORT.md)
  для повного посібника (налаштування, час збірки, кешування для
  класу/сесії); решта прогалин паритету експорту Kivy, що *не*
  впливають на цю гру, перелічені під "Kivy/Android export" у
  репозиторному `TODO.md`.
- **Веб (HTML5):** **підтримується** (з 10.07.2026) — і найкращий
  шлях до iPhone (без встановлення, без підписування). Експортована
  сторінка виявляє, що гра містить події Python `execute_code`, і
  завантажує середовище виконання Pyodide для їх виконання із
  семантикою редактора; торкання/кліки надсилаються як подія
  натискання лівої кнопки миші, а черга малювання рендериться на
  полотно. Перевірено наскрізно в безголовому Chromium (дошка
  рендериться, клік-обмін, блимання, зсув, підрахунок очок). Одна
  застереження: середовище виконання Python завантажується з CDN,
  тому сторінка потребує доступу до інтернету при відкритті — ігри з
  чистими діями (зразки лабіринту/платформера) залишаються повністю
  автономними.
- **Автономний zip:** не перевірено з цим зразком.
