# Match-3 — Уровень 1

Минималистичная, полноценная головоломка «три в ряд» (match-3). Это
первый образец pygm2, **написанный непосредственно в собственном
формате проекта редактора** — образцы лабиринта и платформера были
импортированы из файлов GameMaker 8.x `.gmk`; этот же был написан
напрямую под среду выполнения pygm2.

Он намеренно мал: одна комната, один объект, без скриптов, без
звуков. Вся игра умещается в четырёх событиях единственного
управляющего объекта, что делает его эталонным образцом для действия
`execute_code` и для рендеринга через очередь отрисовки (draw queue).
Более продвинутые версии (плитки на основе спрайтов, звук, уровни)
запланированы как `match3_2` и т. д. — см. *Дорожную карту* ниже.

**Куда это вписывается:** `match3_*` — последняя (и наиболее
отличающаяся) из трёх семей образцов — иная парадигма, а не
постепенный шаг: без встроенных действий, без объектов на каждую
плитку, без плиток на уровне комнаты. Всё (состояние сетки,
столкновения, рендеринг) управляется напрямую из Python-кода
`execute_code`, а не собирается из встроенных действий через много
объектов, как это делают `maze_*` и `plateforme_*`. См.
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays)
для полного прогресса.

**Звук и музыка:** отсутствуют — намеренно, согласно абзацу выше.
(Звук становится возможным начиная с `match3_2`, через примитив
очереди звуков, который ввёл тот образец.)

## Как играть

- **Щёлкните** по плитке, чтобы выбрать её (белый контур), затем
  **щёлкните по соседней плитке**, чтобы поменять их местами.
- Если обмен выстраивает **3 или более плиток одинакового цвета** в
  ряд или столбец, совпавшие плитки на мгновение мигают, уничтожаются,
  а плитки над ними **сдвигаются вниз**, чтобы заполнить пробел; новые
  плитки падают сверху доски.
- Цепные реакции ("каскады") разрешаются волнами, каждая со своей
  анимацией мигания и сдвига.
- Обмен, не создающий совпадения, немедленно отменяется.
- Каждая уничтоженная плитка стоит **10 очков**; наберите **500
  очков**, чтобы победить.

## Структура проекта

| Файл | Назначение |
| ---- | ------- |
| `project.json` | манифест проекта — окно 800×800, 60 кадров/с (`room_speed`), стартовая комната `rm_match3` |
| `rooms/rm_match3.json` | единственная комната; содержит один экземпляр `obj_GridManager` в координатах (0, 0) |
| `objects/obj_GridManager.json` | вся игра: четыре события, каждое с одним действием `execute_code` |
| `sprites/spr_red|blue|green|yellow.*` | квадраты плиток 32×32 — **пока не используются**; зарезервированы для следующей версии на основе спрайтов (см. `CREDITS.txt`) |

Объекта игрока нет, и объекта на каждую плитку тоже нет: доска — это
чистые данные (список цветовых индексов 6×6), принадлежащие одному
невидимому управляющему экземпляру, и всё на экране рисует событие
`draw` этого контроллера через очередь отрисовки среды выполнения
(`self._draw_queue`).

## Как работает код

Всё состояние живёт на управляющем экземпляре (`self.…`), созданное
в событии `create`:

| Атрибут | Значение |
| --------- | ------- |
| `grid` | список 6×6 целых чисел 0–3 (индексы в `palette`); засеян без существующих совпадений |
| `sel` | текущая выбранная клетка `(gx, gy)` или `None` |
| `marked` | набор клеток, которые сейчас совпадают и мигают |
| `flash` / `flash_total` | оставшиеся кадры фазы мигания / её длительность (36 кадров ≈ 0,6 с при 60 кадрах/с) |
| `falling` | словарь `(gx, gy) → пиксели` — насколько выше своей клетки покоя сейчас находится каждая сдвигающаяся плитка |
| `fall_speed` | скорость сдвига в пикселях за кадр (12 → один ряд 96 px за ~0,13 с) |
| `score`, `target`, `won` | состояние счёта (победа при 500) |
| `find_matches` | вспомогательная функция (определена в `create`, сохранена на экземпляре), которая сканирует сетку и возвращает набор всех совпавших клеток |

Игра — небольшой конечный автомат, управляемый событием `step`:

```
idle ──(клики меняют местами, найдено совпадение)──▶ FLASH (отмеченные мигают, 36 кадров)
                                        │ плитки уничтожены, очки добавлены
                                        ▼
                                      FALL (сдвиги уменьшаются на 12 px/кадр)
                                        │ приземление → повторное сканирование сетки
                             новое совпадение ─┴─ без совпадения
                                 │            │
                                 ▼            ▼
                               FLASH        idle
```

- **`create`** — строит начальную сетку (перебрасывая любую плитку,
  которая создала бы немедленное совпадение), инициализирует
  указанное выше состояние и определяет `find_matches`.
- **`mouse_left_press`** — логика выбора/отмены выбора; при соседнем
  обмене применяет его и либо запускает мигание (`marked`, `flash`),
  либо отменяет. Ввод игнорируется, пока идёт мигание или падение, и
  после победы в игре.
- **`step`** — отсчитывает мигание; по истечении засчитывает очки,
  переписывает каждый затронутый столбец на его окончательную раскладку
  и записывает сдвиг в пикселях в `falling` для каждой плитки, которая
  переместилась (выжившие плитки получают `rows_dropped × 96`; плитки
  пополнения входят сверху доски). Пока `falling` не пуст, каждый сдвиг
  уменьшается на `fall_speed`; когда всё приземлилось, повторно
  сканируется на предмет каскадных совпадений и либо повторно запускает
  мигание, либо возвращается к idle.
- **`draw`** — рисует панель доски, затем каждую плитку в
  `позиция_покоя − сдвиг_падения`. Плитки над верхним краем доски
  обрезаются (частично появились) или пропускаются (полностью скрыты),
  поэтому пополнения выглядят так, будто сдвигаются из-под заголовка.
  Отмеченные плитки мигают белым каждые 6 кадров и несут белый контур;
  выбор, строка очков, инструкции и баннер победы рисуются последними.

### Что можно настроить

- Размер доски: `self.cols` / `self.rows` (константы макета `ox`,
  `oy`, `tile` управляют размещением — доска 6×6 с плитками 96 px
  вписывается в окно 800×800).
- Цвета / виды плиток: `self.palette` (добавьте кортеж, чтобы
  получить 5-й цвет; логика переброса и рендерер подхватывают это
  автоматически, но обновите `random.randrange(4)` в `create` и `step`).
- Сложность: `self.target` (очки для победы), `flash_total`,
  `fall_speed`.

## Дорожная карта (запланированные продвинутые версии)

- **[match3_2](../match3_2/README.md)** — сделано: рисует плитки с
  помощью спрайтов вместо цветных прямоугольников, добавляет звуковые
  эффекты для обмена/совпадения/каскада и анимацию сдвига при обмене.
- **[match3_3](../match3_3/README.md)** — сделано: ограничение ходов,

отличие от предыдущей.

## Статус экспорта

- **Test Game (F5) / настольный:** работает — игра запускается на
  стандартной среде выполнения pygame. Проверяется без графического
  интерфейса в прогонах в стиле CI через `tools/smoke_run_samples.py`.
- **Android (.apk) / мобильный (Kivy):** **поддерживается** (с
  03.07.2026). Экспортированная среда выполнения Kivy рендерит очередь
  отрисовки игры (прямоугольники и текст, с осью y, преобразованной в
  систему координат Kivy снизу вверх), отправляет касания как событие
  `mouse_left_press` с координатами комнаты `mouse_x`/`mouse_y` как на
  Android (инвертируя трансформацию полноэкранного масштабирования),
  так и на настольном Kivy, и — поскольку эта игра не имеет событий
  клавиатуры — пропускает наложение виртуального D-pad, которое иначе
  закрывало бы нижний правый угол доски. Экспортированная игра
  проверяется без графического интерфейса в
  `tests/test_kivy_draw_queue_mouse_export.py`, который проигрывает
  полный раунд обмен → мигание → сдвиг через сгенерированный код. Для
  фактической сборки `.apk` дополнительно требуется buildozer (через
  WSL на Windows) — см.
  [`docs/ANDROID_EXPORT.md`](../../docs/ANDROID_EXPORT.md) для полного
  руководства (настройка, время сборки, кэширование для класса/сессии);
  остальные пробелы паритета экспорта Kivy, которые *не* влияют на эту
  игру, перечислены под "Kivy/Android export" в репозиторном `TODO.md`.
- **Веб (HTML5):** **поддерживается** (с 10.07.2026) — и лучший путь
  к iPhone (без установки, без подписи). Экспортированная страница
  обнаруживает, что игра содержит события Python `execute_code`, и
  загружает среду выполнения Pyodide для их выполнения с семантикой
  редактора; касания/клики отправляются как событие нажатия левой
  кнопки мыши, а очередь отрисовки рендерится на холст. Проверено
  сквозным образом в безголовом Chromium (доска рендерится,
  клик-обмен, мигание, сдвиг, подсчёт очков). Одна оговорка: среда
  выполнения Python загружается из CDN, поэтому странице требуется
  доступ в интернет при открытии — игры с чистыми действиями (образцы
  лабиринта/платформера) остаются полностью автономными.
- **Автономный zip:** не проверено с этим образцом.
