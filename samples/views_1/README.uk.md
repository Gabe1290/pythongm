# Views — Рівень 1

Демонстрація камери з прокруткою: кімната (2400×800) **втричі
ширша за вікно 800×600**, тому один екран не може показати все.
Камера (view 0) слідує за гравцем, поки той йде праворуч, розкриваючи
рівень екран за екраном — весь сенс **views** у стилі GameMaker.
Досліджуйте широку кімнату й зберіть усі 18 монет.

**Куди це вписується:** це четверта родина зразків, відмінна від
трьох родин техніки авторства (`maze_*` → `plateforme_*` →
`match3_*`). Те, що вона запроваджує, — це не новий *стиль* авторства,
а нова можливість рушія: **кімната більша за вікно** з **камерою, що
прокручується**. Див.
[`../README.md`](../README.md#progression-how-each-family-is-built-not-just-how-it-plays)
для повного прогресу. Механічно повторно використовує рух у сітці з
`maze_1` (вбудовані дії `test_alignment`/`snap_to_grid`/
`start_moving_direction`) і додає точно одну нову річ: камеру,
увімкнену з події **create** гравця з зареєстрованими діями
`enable_views` + `set_view`.

**Звук і музика:** відсутні — жодного звукового файлу не додано до цього зразка.

## Як грати

- **Клавіші зі стрілками** переміщують гравця на одну клітинку сітки
  (32px) за раз (рух, прив'язаний до сітки, так само як `maze_1`).
- Стіни (`obj_wall`) обрамляють межу кімнати й утворюють кілька
  внутрішніх колон; вони тверді й зупиняють гравця.
- **Камера слідує за гравцем**: йдіть до краю екрана, і вид
  прокручується, щоб тримати вас у кадрі, фіксуючись на межах
  кімнати, тому ви ніколи не бачите за обрамленням стін.
- **Мета:** зберіть усі 18 монет (`obj_coin`). Кожна варта 10 очок
  (показано в заголовку вікна).

## Як налаштована камера

Подія **create** гравця виконує дві зареєстровані дії (без сирого
`execute_code`):

1. `enable_views` — вмикає систему views для кімнати.
2. `set_view` — конфігурує **view 0**: `view_w`/`view_h` `800×600`,
   порт на `(0,0)` розміром `800×600`, `follow` = `obj_player`,
   `hborder` 240 / `vborder` 180 (мертва зона перед тим, як камера
   прокручується), без обмеження швидкості прокрутки. Та сама
   конфігурація також запечена в блок `views` кімнати, тому камера
   правильна з першого кадру на кожній цілі експорту.

## Структура проєкту

| Файл | Призначення |
|---|---|
| `project.json` | Маніфест проєкту — налаштування вікна/кімнати, вбудовані копії ресурсів, і конфігурація `views` кімнати |
| `rooms/room0.json` | Кімната 2400×800 (245 екземплярів: обрамлення стін + колони, гравець, 18 монет) і її блок `views` |
| `objects/obj_player.json` | Гравець: рух у сітці + налаштування камери в події create |
| `objects/obj_coin.json` | Предмет для збору: знищується при дотику гравця, додає 10 до очок |
| `objects/obj_wall.json` | Статична тверда стіна |
| `sprites/` | `spr_player.png`, `spr_wall.png`, `spr_coin.png` + їхні метадані `.json` |
| `CREDITS.txt` | Повідомлення про ліцензування ресурсів |

## Об'єкти

| Об'єкт | Роль | Ключові події |
|---|---|---|
| `obj_player` | Персонаж гравця; рух у сітці + вмикає/конфігурує камеру | create (`enable_views`, `set_view`), keyboard (down/right/up/left/nokey), collision_with_obj_wall |
| `obj_coin` | Предмет для збору вартістю 10 очок | collision_with_obj_player (`destroy_instance` self), destroy (`set_score` +10) |
| `obj_wall` | Статична тверда стіна / межа фіксації камери | (немає — лише пасивний колайдер) |

## Ресурси

3 спрайти (`spr_player`, `spr_wall`, `spr_coin`, кожен 32×32, один
кадр, точне до пікселя зіткнення), 0 звуків. Усі три — просте
мистецтво суцільного кольору CC0, створене для цього зразка — див.
`CREDITS.txt`.

## Що можна налаштувати

- **Розмір кімнати** (`2400×800` у `rooms/room0.json`) — зробіть її
  ширшою/вищою для довшої прокрутки; камера фіксується на тому,
  якою б не була кімната.
- **Межі** (`hborder` 240 / `vborder` 180 в дії `set_view` *та*
  блоці `views` кімнати) — менші межі дозволяють гравцю ближче
  підходити до краю, перш ніж камера рухається; більші тримають його
  більш центрованим.
- **Швидкість прокрутки** — `hspeed`/`vspeed` дорівнюють `-1`
  (миттєве слідування). Встановіть їх на позитивне значення пікселів
  за крок для запізнюючої, згладженої камери.
- **Монети** — додайте/видаліть екземпляри `obj_coin` в
  `rooms/room0.json`.

## Статус експорту

- **Настільний (pygame):** еталонна ціль — перевірено
  `tests/test_views_1_sample.py`, який завантажує цей зразок, виконує
  подію create гравця, і підтверджує, що камера прокручується й
  фіксується, поки гравець проходить усю ширину.
- **Веб (HTML5):** експортований `engine.js` несе ту саму камеру з 8
  views (`tests/test_html5_views.py`, перевірено в Chromium під час
  розробки); конфігурація `views` цього зразка та `set_view` події
  create обидві переносяться в експорт.
- **Мобільний (Kivy/Android):** експортована сцена рендерить усю
  кімнату у Fbo й копіює область кожної видимої view в її порт екрана,
  з вікном операційної системи, розмірним для view (не для кімнати),
  тому камера показує справжній прокручуваний зріз і підтримує кілька
  viewport'ів (`tests/test_kivy_views.py`). Дії
  `enable_views`/`set_view` виведені, тому переконфігурація камери під
  час виконання також працює. *Одне залишкове обмеження:* ціль
  рендерингу для кількох views будується при створенні кімнати, тому
  кімната має мати `views_enabled` у своїй конфігурації (як цей зразок
  має), щоб камера могла рендерити — увімкнення views лише через
  `enable_views` під час виконання на кімнаті, що почала без них, не
  ретроадаптує це на Kivy.
- Узгодженість математики прокрутки між цілями закріплена
  `tests/test_views_export_parity.py`.

Виставлено на вкладці Welcome редактора як "Views — Level 1"
(`widgets/welcome_tab.py`).
