## Введение

В этом руководстве вы создадите **Игру Лунный Посадочный Модуль** — классическую аркадную игру, где вы управляете космическим кораблём, спускающимся на посадочную платформу. Вы должны управлять тягой, чтобы противодействовать гравитации и мягко приземлиться без аварии. Эта игра идеально подходит для изучения физических концепций, таких как гравитация, тяга, скорость и управление топливом.

**Что вы узнаете:**
- Физика гравитации и тяги
- Обнаружение посадки на основе скорости
- Система управления топливом
- Контроль вращения или направления
- Безопасные зоны посадки

**Сложность:** Начинающий
**Пресет:** Средний пресет (физика тяги/топлива полностью основана на
Execute Code, которая не входит в пресет для начинающих)

## Шаг 1: Понять Игру

### Механики Игры
1. Модуль притягивается вниз гравитацией
2. Нажатие ВВЕРХ применяет тягу вверх (использует топливо)
3. ВЛЕВО/ВПРАВО управляет вращением или движением
4. Приземлитесь мягко на платформу, чтобы выиграть
5. Авария, если приземлитесь слишком быстро или промахнётесь
6. Без топлива вы не можете замедлиться!

### Что Нам Нужно

| Элемент | Назначение |
|---------|------------|
| **Модуль** | Корабль, которым вы управляете |
| **Платформа** | Безопасная зона для посадки |
| **Земля** | Местность, вызывающая аварию |
| **Дисплей Топлива** | Показывает остаток топлива |
| **Дисплей Скорости** | Показывает текущую скорость |

## Шаг 5: Создать Объект Модуля

Модуль — главный объект, которым управляет игрок. В отличие от других
руководств по движению в этой вики, его управление должно постепенно
накапливать скорость и следить за запасом топлива, поэтому этот
объект больше опирается на **Control** → **Execute Code** (настоящий
Python — `self` — текущий экземпляр, `game` — исполнитель игры,
`keyboard.check(name)` сообщает, удерживается ли клавиша), чем
предыдущие руководства по движению, но всё же использует
структурированное действие там, где это возможно.

### 5.1 Гравитация И Начальные Переменные

**Событие: Create**
1. Действие: **Move** → **Set Gravity** (Direction: `270`, Gravity:
   `0.05`) — лёгкое притяжение вниз; движок автоматически добавляет
   его к вертикальной скорости модуля каждый кадр, точно так же, как в
   руководстве по платформеру, только слабее.
2. Действие: **Control** → **Execute Code**:

```python
self.thrust_force = 0.1
self.max_speed = 5
self.fuel = 100
self.fuel_use = 0.5
self.landed = False
self.crashed = False
self.safe_speed = 2
```

Система движения этого движка уже отслеживает скорость через
`self.hspeed`/`self.vspeed` и перемещает экземпляр на эту величину
каждый кадр (со встроенным твёрдым столкновением) — не нужно
создавать отдельные переменные `hsp`/`vsp`, как это делала бы ручная
физическая симуляция.

### 5.2 Событие Step — Тяга И Управление

**Событие: Step** — Действие: **Control** → **Execute Code**:

```python
if not self.landed and not self.crashed:
    if keyboard.check('up') and self.fuel > 0:
        self.vspeed -= self.thrust_force
        self.fuel -= self.fuel_use
        if self.fuel < 0:
            self.fuel = 0

    if keyboard.check('left'):
        self.hspeed -= 0.05
    if keyboard.check('right'):
        self.hspeed += 0.05

    # Ограничить максимальную скорость
    self.hspeed = max(-self.max_speed, min(self.max_speed, self.hspeed))
    self.vspeed = max(-self.max_speed, min(self.max_speed, self.vspeed))

    # Не дать модулю выскользнуть за края или над комнатой
    room = game.current_room
    if self.x < 16:
        self.x = 16
        self.hspeed = 0
    if self.x > room.width - 16:
        self.x = room.width - 16
        self.hspeed = 0
    if self.y < 16:
        self.y = 16
        self.vspeed = 0
```

Весь блок находится внутри `if not self.landed and not
self.crashed:`, поэтому тяга и управление останавливаются, как только
игра заканчивается — у объекта нет способа прервать событие
посередине (здесь нет `exit`, как в GML); `if` вокруг остального кода
выполняет ту же задачу.

### 5.3 Столкновение С Платформой

**Событие: Collision with obj_pad**
1. Действие: **Control** → **Test Expression**
   - Expression: `(self.hspeed**2 + self.vspeed**2)**0.5 <=
     self.safe_speed` — скорость посадки — это длина вектора скорости
     (теорема Пифагора), а не переменная `speed` (в этом движке
     `speed` — это *скорость анимации* спрайта, а не величина
     движения — настоящая ловушка для тех, кто пришёл из GameMaker).
   - Then Actions:
     1. **Control** → **Set Variable** (Variable: `landed`, Value: `true`, Scope: `self`)
     2. **Move** → **Stop Movement**
     3. **Move** → **Set Gravity** (Direction: `270`, Gravity: `0`) —
        предотвращает то, что гравитация тихо снова накапливает
        вертикальную скорость у уже приземлившегося модуля
     4. **Output** → **Show Message** (Message: `Идеальная Посадка! Вы Выиграли!`)
   - Else Actions:
     1. **Control** → **Set Variable** (Variable: `crashed`, Value: `true`, Scope: `self`)
     2. **Output** → **Show Message** (Message: `Авария! Слишком быстро!`)
     3. **Room** → **Restart Room**

Текст Show Message — фиксированная строка, он не может показать
реальную скорость посадки. HUD (Шаг 7) уже показывает живую скорость
вплоть до момента столкновения, так что игрок уже видел это число.

### 5.4 Столкновение С Землёй

**Событие: Collision with obj_ground**
1. Действие: **Control** → **Set Variable** (Variable: `crashed`, Value: `true`, Scope: `self`)
2. Действие: **Output** → **Show Message** (Message: `Авария на местности!`)
3. Действие: **Room** → **Restart Room**

## Шаг 6-7: Контроллер Игры

**obj_game_controller** — Событие Draw: находит модуль циклом через
`game.current_room.instances` (тот же шаблон, что и счётчик монет в
руководстве по лабиринту), вычисляет округлённые топливо/скорость в
**Execute Code**, затем показывает их через **Draw Text**/**Draw
Variable**; полные детали по действиям см. в [английской
версии](Tutorial-LunarLander).
