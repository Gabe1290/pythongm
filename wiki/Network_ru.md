# Сеть (многопользовательская игра по LAN)

*[Главная](Home_ru) | [Полный справочник действий](Full-Action-Reference-Network-Actions_ru) | [Расширения](Extensions_ru)*

---

PyGameMaker может превратить проект в **многопользовательскую игру по
локальной сети (LAN)**: один компьютер выступает хостом, остальные
подключаются по локальной сети, а игроки делят общее состояние — таблицу
очков, собственные сообщения и даже аватары друг друга на экране — без
сервера, без учётной записи и без интернета. Это обеспечивает встроенное
[расширение](Extensions_ru) **LAN Multiplayer**, которое включено по
умолчанию.

Входящие в поставку примеры **`reseau_1`–`reseau_3`** — полноценные игровые
примеры: общая комната, в которой двое игроков двигаются вместе, классная
викторина с таблицей очков в реальном времени и кооперативный поиск сокровищ
для двоих.

Поддерживается сегодня: **настольный** экспорт (pygame) как в роли хоста, так
и клиента, и экспорт **HTML5** в роли клиента (страница в браузере
присоединяется к настольному хосту; сама хостом быть не может). Экспорт
**Kivy/Android** запускает игру как однопользовательскую — сетевые действия
там безопасно ничего не делают.

---

## Два уровня

**Уровень A — общая доска.** Без аватаров, только общее состояние: переменные,
которые может читать и записывать каждый игрок, собственные сообщения и список
подключённых. Это самый простой способ добавить многопользовательский режим в
проект — викторина, общая таблица очков, игра-«кто ответит первым» с кнопкой.

**Уровень B — сетевые экземпляры.** Экземпляры, создаваемые хостом (игроки,
враги, предметы), которые автоматически появляются и двигаются на каждом
компьютере, а также аватары, принадлежащие игроку: каждый управляет своим
локально, а остальные видят плавно интерполируемую копию.

---

## Как это работает

- Один игрок вызывает **Создать игру**, обычно из события Create объекта-
  контроллера комнаты. Этот компьютер становится **хостом** — компьютеры всех
  остальных игроков подключаются к нему. `global.player_id` становится `0`.
- Остальные игроки вызывают **Присоединиться к игре** с LAN-адресом хоста (или `"auto"`,
  чтобы показать встроенный экран подключения, который сам находит хосты в
  сети). `global.player_id` назначает хост (`1`, `2`, ...).
- Если хост недоступен, **игра продолжается как однопользовательская** —
  подключение никогда не блокирует и не ломает игру.
- Идентичность игрока и состояние подключения всегда доступны как глобальные
  переменные: `global.is_host`, `global.player_id`, `global.player_count`,
  `global.network_role`, `global.network_connected`.
- **Пишите логику игры обычным действием «Если»**, например
  `global.is_host == 1`, чтобы оставить подготовку (например, создание врагов)
  только хосту — никакие особые «сетевые условия» не нужны.
- Общая переменная, заданная через **Задать общую переменную**, читается *везде* как
  `global.<имя>` — в том числе на компьютере, который её задал.
- **Собственные сообщения** (**Отправить сетевое сообщение**) позволяют сообщить о
  событии по имени с небольшим приложенным значением — нажатие кнопки, выбранный
  ответ, флажок «готов».

## Действия (категория **Сеть**)

| Действие | Что делает |
|----------|------------|
| **Создать игру** | Стать хостом. По желанию показывает комнату ожидания с кнопкой «Старт». |
| **Присоединиться к игре** | Подключиться к хосту по адресу (или `"auto"` для встроенного экрана подключения). |
| **Покинуть игру** | Отключиться (или перестать быть хостом) и очистить сетевые глобальные переменные. |
| **Начать сетевую игру** | Только хост: закрыть комнату ожидания и сообщить всем, что пора начинать. |
| **Задать общую переменную** | Записать переменную, которую каждый компьютер может читать как `global.<имя>`. |
| **Прочитать общую переменную** | Скопировать общую переменную в глобальную (для использования в вычислении). |
| **Отправить сетевое сообщение** | Разослать всем собственное именованное сообщение с данными. |
| **Создать сетевой объект** | Только хост: создать экземпляр, который появится у всех клиентов. |
| **Синхронизировать этот экземпляр** | Пометить действующий экземпляр как реплицируемый между компьютерами. |
| **Задать владельца экземпляра** | Дать конкретному игроку локальное управление синхронизируемым экземпляром. |
| **Если я управляю этим экземпляром** | Условие: оставляет логику управления только на компьютере-владельце. |
| **Назначить сетевую клавишу** | Связать локальную клавишу с именованным вводом, который может читать хост. |
| **Если игрок нажимает** | Условие (хост): удерживает ли данный игрок именованный ввод? |
| **Задать частоту синхронизации** | Настроить частоту снимков хоста и задержку интерполяции у клиентов. |

Все параметры смотрите в [Полном справочнике действий](Full-Action-Reference-Network-Actions_ru).

## События (категория **Сеть**)

Они срабатывают на каждом экземпляре, чей объект их обрабатывает, на каждом
затронутом компьютере:

| Событие | Срабатывает, когда |
|---------|--------------------|
| **Network Ready** | Клиент завершает подключение к хосту (хост не вызывает его для себя). |
| **Player Joined** | Подключается новый игрок. `global.network_sender` / `global.network_player_name` называют его. |
| **Player Left** | Игрок отключается. |
| **Network Message** | Приходит **Отправить сетевое сообщение** — `global.network_event` / `global.network_data` / `global.network_sender`. |
| **Network Game Started** | Хост вызывает **Начать сетевую игру**. |
| **Connection Lost** | Обрывается соединение клиента с хостом. Игра продолжается — исчезают только «призраки» этого игрока. |

## Минимальный пример общей комнаты (уровень A)

В невидимом объекте-контроллере комнаты:

- **Create:** `Создать игру`, если это компьютер учителя, иначе `Присоединиться к игре` с
  его IP (или `"auto"`).
- **Create:** `Задать общую переменную` `round = 1` (только хост, под защитой
  `global.is_host == 1`).
- Где угодно: `draw_text`, показывающий `global.round` — все игроки видят одно
  и то же значение.

## Минимальный пример общих аватаров (уровень B)

В событии Create объекта игрока:

- `Синхронизировать этот экземпляр` — этот экземпляр теперь реплицируется.
- На **хосте**: `Создать сетевой объект` создаёт по одному экземпляру игрока на
  каждого подключающегося (в обработчике **Player Joined**), затем
  `Задать владельца экземпляра` с номером этого игрока.
- Код движения под защитой `Если я управляю этим экземпляром` выполняется только на
  компьютере игрока-владельца; на всех остальных экземпляр — плавно
  интерполируемый «призрак».

## Заметки и ограничения

- **TCP, только LAN.** Без обхода NAT и без игры через интернет — оба
  компьютера должны быть доступны в одной локальной сети (школьный Wi-Fi или
  проводной класс). Wi-Fi с изоляцией клиентов (обычное дело в управляемых
  школьных сетях) одинаково блокирует и обнаружение, и прямое подключение;
  самый надёжный вариант — проводной класс.
- **Порты 45782 (TCP)** и **45783 (UDP, обнаружение)** — перед использованием в
  управляемой сети спросите школьную ИТ-службу и ожидайте запрос брандмауэра
  при первом запуске в роли хоста.
- Клиент в браузере (экспорт HTML5) подключается к порту на единицу выше
  порта хоста, например `45783`, если хост использует порт по умолчанию, —
  это происходит автоматически.
- Потеря хоста обрабатывается мягко: собственная игра клиента продолжается;
  исчезают только «призраки» других игроков, и срабатывает **Connection Lost**,
  чтобы вы могли показать сообщение.
- Если расширение LAN Multiplayer **отключено**, эти действия и события просто
  ничего не делают — см. [Расширения](Extensions_ru).
