# Мережа (багатокористувацька гра по LAN)

*[Головна](Home_uk) | [Повний довідник дій](Full-Action-Reference-Network-Actions_uk) | [Розширення](Extensions_uk)*

---

PyGameMaker може перетворити проект на **багатокористувацьку гру по локальній
мережі (LAN)**: один комп'ютер виступає хостом, решта приєднуються через
локальну мережу, а гравці ділять спільний стан — таблицю очок, власні
повідомлення і навіть аватари одне одного на екрані — без сервера, без
облікового запису й без інтернету. Це забезпечує вбудоване
[розширення](Extensions_uk) **LAN Multiplayer**, яке ввімкнене за
замовчуванням.

Вбудовані приклади **`reseau_1`–`reseau_3`** — повноцінні ігрові приклади:
спільна кімната, в якій двоє гравців рухаються разом, класна вікторина з
таблицею очок у реальному часі та кооперативний пошук скарбів для двох.

Підтримується сьогодні: **настільний** експорт (pygame) і як хост, і як клієнт,
та експорт **HTML5** як клієнт (сторінка в браузері приєднується до
настільного хоста; сама хостом бути не може). Експорт **Kivy/Android**
запускає гру як однокористувацьку — мережеві дії там безпечно нічого не
роблять.

---

## Два рівні

**Рівень A — спільна дошка.** Без аватарів, лише спільний стан: змінні, які
може читати й записувати кожен гравець, власні повідомлення та перелік
підключених. Це найпростіший спосіб додати багатокористувацький режим до
проекту — вікторина, спільна таблиця очок, гра «хто відповість першим» із
кнопкою.

**Рівень B — мережеві екземпляри.** Екземпляри, які створює хост (гравці,
вороги, предмети), що автоматично з'являються й рухаються на кожному
комп'ютері, а також аватари, що належать гравцю: кожен керує своїм локально,
а решта бачить плавно інтерпольовану копію.

---

## Як це працює

- Один гравець викликає **Створити гру**, зазвичай із події Create об'єкта-
  контролера кімнати. Цей комп'ютер стає **хостом** — комп'ютери всіх інших
  гравців підключаються до нього. `global.player_id` стає `0`.
- Інші гравці викликають **Приєднатися до гри** із LAN-адресою хоста (або `"auto"`,
  щоб показати вбудований екран підключення, який сам знаходить хостів у
  мережі). `global.player_id` призначає хост (`1`, `2`, ...).
- Якщо хост недоступний, **гра триває як однокористувацька** — приєднання
  ніколи не блокує і не ламає гру.
- Ідентичність гравця та стан підключення завжди доступні як глобальні змінні:
  `global.is_host`, `global.player_id`, `global.player_count`,
  `global.network_role`, `global.network_connected`.
- **Пишіть логіку гри звичайною дією «Якщо»**, наприклад
  `global.is_host == 1`, щоб залишити підготовку (скажімо, створення ворогів)
  лише хосту — жодні особливі «мережеві умови» не потрібні.
- Спільна змінна, задана через **Задати спільну змінну**, читається *всюди* як
  `global.<ім'я>` — зокрема й на комп'ютері, який її задав.
- **Власні повідомлення** (**Надіслати мережеве повідомлення**) дають змогу повідомити
  про подію за назвою з невеликим доданим значенням — натискання кнопки,
  обрана відповідь, прапорець «готовий».

## Дії (категорія **Мережа**)

| Дія | Що робить |
|-----|-----------|
| **Створити гру** | Стати хостом. За бажанням показує кімнату очікування з кнопкою «Старт». |
| **Приєднатися до гри** | Підключитися до хоста за адресою (або `"auto"` для вбудованого екрана підключення). |
| **Покинути гру** | Від'єднатися (або припинити хостинг) і очистити мережеві глобальні змінні. |
| **Почати мережеву гру** | Лише хост: закрити кімнату очікування й повідомити всім, що час починати. |
| **Задати спільну змінну** | Записати змінну, яку кожен комп'ютер може читати як `global.<ім'я>`. |
| **Прочитати спільну змінну** | Скопіювати спільну змінну в глобальну (для використання в обчисленні). |
| **Надіслати мережеве повідомлення** | Розіслати всім власне іменоване повідомлення з даними. |
| **Створити мережевий об'єкт** | Лише хост: створити екземпляр, який з'явиться в усіх клієнтів. |
| **Синхронізувати цей екземпляр** | Позначити чинний екземпляр як реплікований між комп'ютерами. |
| **Задати власника екземпляра** | Дати конкретному гравцеві локальне керування синхронізованим екземпляром. |
| **Якщо я керую цим екземпляром** | Умова: залишає логіку керування лише на комп'ютері-власнику. |
| **Призначити мережеву клавішу** | Пов'язати локальну клавішу з іменованим уведенням, яке може читати хост. |
| **Якщо гравець натискає** | Умова (хост): чи утримує певний гравець іменоване уведення? |
| **Задати частоту синхронізації** | Налаштувати частоту знімків хоста та затримку інтерполяції в клієнтів. |

Усі параметри дивіться в [Повному довіднику дій](Full-Action-Reference-Network-Actions_uk).

## Події (категорія **Мережа**)

Вони спрацьовують на кожному екземплярі, чий об'єкт їх обробляє, на кожному
задіяному комп'ютері:

| Подія | Спрацьовує, коли |
|-------|------------------|
| **Network Ready** | Клієнт завершує підключення до хоста (хост не викликає її для себе). |
| **Player Joined** | Підключається новий гравець. `global.network_sender` / `global.network_player_name` називають його. |
| **Player Left** | Гравець від'єднується. |
| **Network Message** | Надходить **Надіслати мережеве повідомлення** — `global.network_event` / `global.network_data` / `global.network_sender`. |
| **Network Game Started** | Хост викликає **Почати мережеву гру**. |
| **Connection Lost** | З'єднання клієнта з хостом обривається. Гра триває — зникають лише «привиди» цього гравця. |

## Мінімальний приклад спільної кімнати (рівень A)

У невидимому об'єкті-контролері кімнати:

- **Create:** `Створити гру`, якщо це комп'ютер учителя, інакше `Приєднатися до гри` з
  його IP (або `"auto"`).
- **Create:** `Задати спільну змінну` `round = 1` (лише хост, під захистом
  `global.is_host == 1`).
- Будь-де: `draw_text`, що показує `global.round` — усі гравці бачать те саме
  значення.

## Мінімальний приклад спільних аватарів (рівень B)

У події Create об'єкта гравця:

- `Синхронізувати цей екземпляр` — цей екземпляр тепер реплікується.
- На **хості**: `Створити мережевий об'єкт` створює по одному екземпляру гравця на
  кожного, хто підключається (в обробнику **Player Joined**), потім
  `Задати власника екземпляра` з номером цього гравця.
- Код руху під захистом `Якщо я керую цим екземпляром` виконується лише на комп'ютері
  гравця-власника; на всіх інших екземпляр — плавно інтерпольований «привид».

## Нотатки й обмеження

- **TCP, лише LAN.** Без обходу NAT і без гри через інтернет — обидва
  комп'ютери мають бути досяжні в одній локальній мережі (шкільний Wi-Fi або
  дротовий клас). Wi-Fi з ізоляцією клієнтів (звичайна річ в керованих
  шкільних мережах) однаково блокує і виявлення, і пряме підключення;
  найнадійніший варіант — дротовий клас.
- **Порти 45782 (TCP)** і **45783 (UDP, виявлення)** — перед використанням у
  керованій мережі запитайте шкільну ІТ-службу й очікуйте запит брандмауера
  під час першого запуску в ролі хоста.
- Клієнт у браузері (експорт HTML5) підключається до порту на одиницю вищого за
  порт хоста, наприклад `45783`, якщо хост використовує типовий, — це
  відбувається автоматично.
- Втрата хоста обробляється м'яко: власна гра клієнта триває; зникають лише
  «привиди» інших гравців, і спрацьовує **Connection Lost**, щоб ви могли
  показати повідомлення.
- Якщо розширення LAN Multiplayer **вимкнене**, ці дії та події просто нічого
  не роблять — див. [Розширення](Extensions_uk).
