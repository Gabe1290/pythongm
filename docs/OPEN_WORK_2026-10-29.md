## Part A — can be done now

- [~] **A1. The native crash in the full test run — investigated, NOT reproduced,
  hardened, kept open as "watch".** The full suite died 3 times with `Windows
  fatal exception: access violation` inside a QtWebEngine Blockly test (no Python
  traceback). *Findings (2026-10-29):*
  - It does **not** reproduce on demand: 6 runs of everything up to and including
    `test_blockly_block_audit_roundtrip.py`, 2 full-suite runs (7,721 passed), 40
    runs of the two WebEngine files alone and 25 with `PYGM_GC_COLLECT_PER_TEST=1`
    all passed. So it is not "the tests before it" and not my recent changes.
  - Windows kept three older dumps (1 Oct) of the same crash class:
    `Qt6Quick.dll + 0x11593b` every time, `Qt6WebEngineWidgets`/`Qt6QuickWidgets`
    and shiboken frames on the stack: the crash is inside the `QWebEngineView`'s own
    QQuickWidget. Each Qt WebEngine view is an in-process Chromium page.
  - Forcing software rendering (`QT_QUICK_BACKEND=software`) is **not** a fix: the
    default path never initialises Qt Quick's scene graph for an unshown view, and
    the setting only makes Chromium log GL-context errors.
  - Two weak spots were found and removed: `test_blockly_generated_block_i18n.py`
    called `widget.deleteLater()` on four widgets that each own a WebEngine view and
    never ran the deferred delete; the round-trip fixture's view was freed by
    refcounting the instant the fixture returned. Both now go through
    `conftest.dispose_qt_widget`, which closes the widget and runs the deletion.
    **Unproven**: with no reproduction there is no before/after rate.
  - `tools/analyze_crash_dump.py` names the faulting DLL, offset and caller chain
    of a `python.exe` dump in seconds. *If it crashes again:* run it on the newest
    dump in `%LOCALAPPDATA%\CrashDumps`; the same `Qt6Quick.dll + 0x11593b` means
    the same bug, a different spot means the hardening moved it.
  - *Done when:* the full suite has run green five times in a row after the next
    day or two of normal use, or a dump shows a different cause.
