## What v2 adds

**Two teaching tiers:**
- **Tier A — shared blackboard:** shared variables (`global.*` mirror + get/set actions), custom `send_network_message` + a `network_message` event, player identity (`player_id`, `player_count`, `is_host`). Enough for quizzes, turn-based/board games, draw-together. Robust on flaky Wi-Fi.
- **Tier B — networked instances:** `sync_instance`, `set_instance_owner` (client-authoritative avatar), `network_spawn`/replicated destroy, named inputs (`bind_network_input` + `remote_input(player, name)`), 20 Hz snapshots with 100 ms interpolation. Real-time co-op movement.

**Model:** authoritative host, no netcode cleverness — clients send intent, render interpolated ghosts, own only their avatar. Teaching rule baked into every sample: *cosmetic runs everywhere, gameplay runs under `if is_host()`*.

**Core changes:** at most **one** new small read-only hook (`register_expression_names`, so `is_host()`/`shared("x")` work inside expressions) — and it's explicitly cuttable; `global.*` reads cover every case without it. Everything else rides existing extension surfaces (`PLUGIN_ACTIONS`, `PLUGIN_EVENTS`, `PLUGIN_FRAME_UPDATES`, `extension_state`).

**Connection UX:** hand-rolled UDP discovery beacon (no zeroconf dep) + a French built-in connect/lobby overlay, with manual-IP entry as the load-bearing path. IDE "Test Game (2 players)" button. The plan leans hard on real school-LAN constraints — AP client isolation, firewall prompts, Chromebooks — as the things the design works *around*.

**Export:** desktop full; HTML5 via a hand-rolled WebSocket listener on the desktop host (no `websockets` pip dep), possibly its own plan; Kivy/Android explicitly out of scope (no-op placeholder).

**Phasing:** 4 (protocol v2 + netids + sanitize) → 5 (session + student API) → 6 (connection UX) → 7 (HTML5) → 8 (samples `reseau_1..4` + polish), one commit per checkbox, plus a manual-QA list that genuinely needs two machines.

## Classroom‑LAN things that can still block it
