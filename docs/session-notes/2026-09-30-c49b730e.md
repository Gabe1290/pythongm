No, that isn't normal. It's a bug: the beginner preset is small, but the Blockly toolbox only applies it to part of the blocks.

**What the preset intends:** 40 of the 86 built-in blocks, in 10 categories ([blockly_config.py:245](config/blockly_config.py#L245)). Each block is commented with the beginner tutorial that needs it. That's a reasonable beginner set.

**What actually reaches the toolbox:** those 40, plus Math and Logic (always shown), plus about 82 auto-generated blocks the preset never filters. The Blockly toolbox builder ([blockly_workspace.html:2789-2797](editors/object_editor/blockly/blockly_workspace.html#L2789-L2797)) creates a block for every action that has no hand-made block. The preset only filters these when their category name matches one of the 10 built-in category names. Every other category is added in full, with no preset check:

| Category | Blocks | Notes |
|---|---|---|
| Network | 22 | LAN multiplayer: `host_game`, `end_turn`… |
| Game | 20 | `draw_line`, `draw_sprite`, `draw_ellipse`… |
| 3D View | 18 | raycast and Block World: `break_block`, `craft_item`, `draw_doom_hud`… |
| Particles | 8 | |
| Audio | 6 | Intentional: always visible, by an earlier decision |
| Score | 5 | `test_lives`, `test_score`… The built-in category is named "Score/Lives/Health", so these slip past the filter |
| Views | 2 | |
| Grid | 1 | |

So a beginner sees about 120 blocks in about 18 categories instead of about 40 in 10. Apart from Audio, none of this looks deliberate. It probably built up as extensions (raycast, Block World, multiplayer, particles) added actions that nobody ever tied to the preset. The code comments only mention Audio as an intended always-visible category.

I got this by comparing the preset against the live action list and the toolbox code. I haven't rendered the toolbox and counted, so the exact number could be slightly off, but the problem is clear.

**What I found beyond my first answer:**
- **The action-list editor has the same bug.** The right-click "add action" menu shows any action that has no Blockly block, whatever the preset. The published wiki Beginner-Preset pages are generated from that same code, so they list those actions too.
- **Filtering alone would break other presets.** Presets only know the 86 built-in blocks. Applying them to the 82 auto-generated ones would also strip those out of full, intermediate and people's saved custom configs, so the presets have to learn about them first.
- **The fix will hide a few blocks that beginner samples use.** Blocks like `restart_game`, `set_window_caption` and `set_draw_color` are used by maze_1–4, plateforme_3, treasure and sky_strike_1. They're only visible today because of this bug.

**How it will work:**
- **One rule, used by both editors.** A single Python function decides what's visible, and both the Blockly toolbox and the action-list editor call it.
- **Presets apply to every block**, except Audio, which stays always visible as decided earlier.
- **Extension categories need the extension switched on for the project.** 3D View, Network and the others only show when that's true, and then they show in every preset. A project counts as having an extension on if you tick it in Project Settings, or if the project already uses its actions. That second rule means existing samples and projects keep working without any migration.
- **You can't switch off an extension the project uses.** Its checkbox is locked, with a note saying how many actions use it.
- **Thymio keeps its own existing rule**: its blocks show when the project has playgrounds.

**Units, one commit each:**
1. The Python function, with tests.
2. Teaching the presets about the generated actions. The trimming is limited to beginner; the other presets keep what they show today, minus extension categories.
3. Blockly toolbox fix.
4. Action-list editor fix, and regenerating the preset docs.
5. The project setting and checkboxes, with translations in all 10 languages.
6. Wiki updates, and trying a screenshot of the real toolbox.

**Decision for you before unit 2:** which of those sample blocks should the beginner preset include? I recommend adding `restart_game`, `set_window_caption` and `set_draw_color`, and leaving out `set_draw_font` and `draw_sprite`. A sample that uses a block missing from the toolbox still opens and runs; students just can't drag in a new one.
