## [2026-09-24] User

> How can a user change the following: Setting PYGM_ALLOW_MULTIPLE_INSTANCES=1

### Claude

It's an ordinary environment variable, and there's no setting or menu for it in the IDE. [main.py:362](main.py#L362) reads it once at startup, and only the exact value `1` turns the guard off. `true` or `yes` won't work.

**Linux/macOS (bash), for one launch:**
```bash
PYGM_ALLOW_MULTIPLE_INSTANCES=1 python3 main.py
```

**Linux/macOS, for the whole terminal session:**
```bash
export PYGM_ALLOW_MULTIPLE_INSTANCES=1
python3 main.py
```

**Windows PowerShell:**
```powershell
$env:PYGM_ALLOW_MULTIPLE_INSTANCES = "1"
py -3.12 main.py
```

**Windows cmd:**
```cmd
set PYGM_ALLOW_MULTIPLE_INSTANCES=1
py -3.12 main.py
```

- **Persistent setting:** Put the `export` line in `~/.bashrc`, or on Windows use `setx PYGM_ALLOW_MULTIPLE_INSTANCES 1`. `setx` only affects newly opened terminals.
- **Packaged builds or desktop shortcuts:** A launcher started from the desktop or Start menu won't inherit a terminal's variable. You'd need a wrapper script, or a system-level variable, that sets it before starting the app.
- **Not documented yet:** The variable appears only in the commit message and a code comment, not in the README or wiki. If students or teachers need to know about it, I can add a line to the docs.

I'd leave it off in the classroom. The guard exists to stop the multi-process save collision. Turning it on is only worth it for a developer running two IDEs on two different projects.
