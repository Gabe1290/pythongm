That error is Debian/Ubuntu protecting the system Python, so you need a virtual environment. There's a second problem: the only Python on this machine is **3.14**, and pygm2 supports 3.10–3.13. pygame and PySide6 may not have builds for 3.14, so a 3.14 venv could fail to install or misbehave.

The simplest fix is `uv`, which can download a supported Python for you without touching the system one:

```bash
# 1. Install uv (one time)
sudo apt install pipx && pipx install uv
#   or: curl -LsSf https://astral.sh/uv/install.sh | sh
# Open a new terminal afterwards so uv is on your PATH.

# 2. Create a Python 3.12 venv in the repo and install the dependencies
cd ~/projects/pythongm
uv venv --python 3.12 venv
uv pip install --python venv/bin/python -r requirements.txt

# 3. Run the IDE
venv/bin/python main.py
```

After that, run it with `venv/bin/python main.py`, or `source venv/bin/activate` first and then use `python main.py`. `venv/` is already in `.gitignore`, so it won't get committed.

If you'd rather try 3.14 first, `python3 -m venv venv && venv/bin/pip install -r requirements.txt` might work. If pygame or PySide6 fails to install, use the uv route above.

> Can we install venv without uv

### Claude

Yes, but you still need a Python other than 3.14. The repo's own `requirements.txt` says 3.14 isn't supported yet: pygame, kivy, watchdog and PySide6 have no pre-built packages for it. Also, `python3-venv` isn't installed on this machine (`ensurepip` is missing), so even a 3.14 venv would fail right now.

There are two ways to get Python 3.12 without uv on Ubuntu 26.04.

**Option 1: deadsnakes PPA** (the usual Ubuntu way):

```bash
sudo add-apt-repository ppa:deadsnakes/ppa
sudo apt update
sudo apt install python3.12 python3.12-venv

cd ~/projects/pythongm
python3.12 -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python main.py
```

I'm not sure the PPA already has packages for 26.04, since it usually lags new releases. If `apt install python3.12` says it can't find the package, use option 2.

**Option 2: pyenv** (compiles Python from source, works on any release):

```bash
sudo apt install build-essential libssl-dev zlib1g-dev libbz2-dev \
  libreadline-dev libsqlite3-dev libffi-dev liblzma-dev tk-dev libncurses-dev
curl https://pyenv.run | bash
# add the three lines the installer prints to ~/.bashrc, then open a new terminal
pyenv install 3.12

cd ~/projects/pythongm
~/.pyenv/versions/3.12.*/bin/python -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python main.py
```

Compiling takes a few minutes. Your system Python 3.14 is left alone in both cases.

### Claude

That crash comes from Qt's GNOME integration, not from the project or your install. Qt reads a GNOME setting called `antialiasing` that newer GNOME releases (like the one on Ubuntu 26.04) have removed, and GLib aborts the whole program when a missing setting is read. The repo doesn't set Qt's platform theme anywhere, so it gets the GNOME one by default.

Tell Qt to skip that integration:

```bash
QT_QPA_PLATFORMTHEME=xdgdesktopportal venv/bin/python main.py
```

If that still crashes, try `QT_QPA_PLATFORMTHEME=generic` instead. With either one, file dialogs and colours may look slightly less GNOME-native, but the IDE behaves the same.

To avoid typing it every time, add this to `~/.bashrc`:

```bash
export QT_QPA_PLATFORMTHEME=xdgdesktopportal
```

Once you know which value works, I can make `main.py` set it by default when it sees this GNOME version, so a fresh clone doesn't crash on Ubuntu 26.04. Let me know if you want that.
