## [2026-08-19] User

> I would like to set up a small web site as an "advertisement" for my programming courses using PyGameMaker. I assume that I can propose a few games that have been exported in HTML format.
> Can I change he name of the HTML file and the game contained within will still execute?

### Claude

Let me check how the HTML5 exporter structures its output files to give you an accurate answer.

Yes — with the default export settings, renaming is completely safe.

By default (`export/HTML5/html5_exporter.py:399-475`), the HTML5 export produces **one fully self-contained `.html` file**: the engine code, game data, sprites, and sounds are all inlined directly into that file (as embedded `<script>` blocks / base64 data). Nothing inside references its own filename, so you can rename it to anything (`space_shooter.html`, `demo1.html`, etc.) and it'll run exactly the same — just double-click it or link to it from your site.

One exception to know about: if you enable the **"external assets"** export option, it instead writes a *folder* (separate `engine.js`, `pako.min.js`, an `assets/` folder, plus the `.html`). Renaming the `.html` file in that mode is still fine on its own, since it references those files by relative path, not by its own name. But if you *additionally* enable the **PWA** option on top of that, the generated `manifest.json` and `sw.js` hardcode the original HTML filename (for install/offline caching) — renaming the `.html` in that specific combo would break the "install as app" / offline-caching behavior unless you also edit those two files.

So: for a simple "advertisement" site with a handful of playable demos, just use the default single-file export and rename freely.
