# Translation catch-up to French (2026-11-21)

**Goal:** every shipped language translates every interface string the code
uses that French translates. Replaces the TODO.md entry "pt/ja/zh (and
es/pt/de-split) have drifted behind fr".

**Measured** with `scripts/i18n_catchup.py report` (counts only strings the code
really passes to `tr()` / `QCoreApplication.translate()`; French also holds stale
entries, so the raw catalogue sizes overstate the gap):

| language | missing | contexts |
|---|---|---|
| de, it, ru, sl, uk (split catalogues) | 238 each | 30 |
| ja, pt, zh | 119 each | 18 |
| es | 112 | 17 |
| pl | 10 | 2 |

About 270 distinct source strings, ~1,550 translations in all.

**Method.** `scripts/i18n_catchup.py worklist OUT.json` lists each missing
string with the French as a hint and the languages lacking it. A batch file
`{context: {source: {lang: text}}}` is written per unit and applied with
`scripts/i18n_catchup.py apply` (it routes each string to the right file, revives
an empty vanished copy in place, refuses a string the code does not use, and
flags a lost `{0}`/`%1` placeholder), then `scripts/compile_translations.py`.
Conventions carried over: CJK menu mnemonics keep the English letter in
parentheses (`ファイル(&F)`); translation values are plain characters (the tool
escapes); Brazilian Portuguese as in the existing pt catalogue; terminology
matched to each language's existing catalogue for the same screen.

**Per unit:** apply, compile, `tests/test_dead_translations.py` +
`tests/test_i18n_catchup.py`, commit, push, tick here.
