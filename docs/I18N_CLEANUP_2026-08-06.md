## Section H — pt/ja/zh UI translation (deferred, its own multi-session tier)

**Correction (2026-08-06, same day the plan was written):** the original
plan assumed `pygamemaker_pt.ts`/`_ja.ts`/`_zh.ts` held stale-but-real
translated content just needing compilation. Checked before compiling
(per the plan's own "verify before trusting" caution) and found
otherwise, **twice over**:

1. All 289 `<message>` entries in each file are `type="unfinished"` — zero
   translated strings exist. `grep -c "<translation>"` (the non-empty
   form) returns 0 for all three.
2. Even if translated, 289 messages is a small, old snapshot (dated
   Nov 2025) against the current UI — `pygm2_de.ts`, a fully-maintained
   language, runs ~8,756 lines / far more entries. Translating just these
   289 would leave most of the current UI in English regardless.

User decision: **do this properly, against the current full string
catalog, as its own deferred multi-session tier** — not attempted this
session, not treated as a quick compile-and-done task. Work order and
scope, once a future session picks this up:

- [ ] Establish the source string list to translate FROM: either run
  `lupdate` fresh against the current codebase (this repo otherwise never
  runs it — see `translations/README.md`'s note on `type="vanished"` — so
  confirm the tool still works before relying on it), or use a currently-
  complete language's `.ts` (e.g. `pygm2_de.ts`) as the up-to-date list of
  `<source>` English strings to translate against. Either way, do NOT
  reuse `pygamemaker_pt.ts`'s 289-entry list as the scope — it's
  confirmed incomplete.
- [ ] pt: translate the full current string catalog into `pygm2_pt.ts`,
  compile to `pygm2_pt.qm`.
- [ ] ja: same, `pygm2_ja.ts` → `pygm2_ja.qm`.
- [ ] zh: same, `pygm2_zh.ts` → `pygm2_zh.qm`.
- [ ] Verify all three appear in Tools > Language
  (`core/language_manager.py::_discover_languages()` globs `*.qm`) and
  spot-check translated strings against the running UI, not just file
  content.
- [ ] Delete the now-superseded `pygamemaker_pt.ts`/`_ja.ts`/`_zh.ts` once
  their real replacements exist.

**Cost note for whoever picks this up:** likely comparable to or larger
than one language's worth of Section J (the ~8,756-line `pygm2_de.ts` is
roughly the same order of magnitude as this session's whole wiki-page
fix), times three languages, times the added difficulty of Japanese/
Chinese specifically warranting extra care on technical-term accuracy.
Budget as its own multi-session arc, not a side task.
