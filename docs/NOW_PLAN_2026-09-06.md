# What we can do now — plan, 2026-09-06

Written after `docs/POST_1_0_REFACTOR.md` closed (all four file splits plus the
`action_handlers` teardown). Every large initiative in `docs/PROJECT_STATUS.md`
is now either finished or blocked on hardware, so this plan exists to answer
one question: **what is actually workable today.**

**The blocking constraint:** LAN multiplayer cannot be tested (it needs two
machines on a school LAN), there is no Android device to hand, and no Mac. So
everything below either needs no hardware at all, or needs only this Windows
box and a browser.

Same discipline as the refactor: one unit per commit, pushed immediately, full
suite as the gate, so a mid-session stop loses nothing.

## Track A — code work, no hardware needed

### A1. Extension action names are untranslated — DONE 2026-09-06

Shipped in three commits (`665ea14a`, `9c1855a6`, `407ba076`). All 37 actions
contributed by plugins and folder extensions now resolve in all ten shipped
languages, in both Qt contexts.

- [x] **A1.1** Source-language rule: extension actions are authored in
      **English** and localized through the catalogues, like the rest of the
      codebase. *Prerequisite found while scoping and fixed first:* action
      descriptions and parameter tooltips were displayed with a bare `QLabel`,
      never `tr()`, so **no description in the app could be translated at
      all** — zero appear in any catalogue because there was nothing for
      `lrelease` to collect. Without fixing that, re-authoring the multiplayer
      extension would have handed French teachers English descriptions.
- [x] **A1.2** `extensions/multiplayer_lan` re-authored in English — 97
      strings across 15 actions, 6 events, their descriptions and 31 parameter
      labels, plus the `Réseau` → `Network` category — with every French
      string added to `pygm2_fr.ts` **in the same commit**, so French users
      lost nothing at any point in the history.
- [x] **A1.3** All 37 names translated into de/es/fr/it/ja/pt/ru/sl/uk/zh.
- [x] **A1.4** `tests/test_extension_action_i18n.py`: every name resolves in
      every language, driven through the real `LanguageManager`.

**Scope correction worth keeping.** The count is **37, not 35**: `check_sound`
and `stop_sound` sit in the Audio category but are declared statically in core,
so "what did `load_all_plugins` add?" misses them. Filtering by *category* is
what the user actually sees in the palette.

**Still open, and bigger than A1 was:** action *descriptions* and *parameter
labels* remain untranslated — 279 distinct strings, ~2,790 translations. That
gap affects **core** actions equally, so it is not extension work; it now has
somewhere to go, since those strings are finally `tr()`-wrapped.

**Landmines this pass hit, all now guarded:** a `type="vanished"` entry is
dropped by `lrelease`, so three audio actions carried correct translations that
never reached a user; appending a live duplicate beside a vanished one does not
resolve either (two messages, one source, one context) — they must be
un-vanished in place; and a module-scoped translator fixture let French mask a
missing German string, then leaked French into ten unrelated widget tests.

### A3. Block World renders far below its own target frame rate

Measured, not assumed (2026-08-21): `block_world_1` ~9.6 fps and
`block_world_2` ~3.85 fps against a project-configured 30 fps. Movement is
correct; the renderer cannot keep up, so held-key movement advances only once
per rendered frame — roughly 3× slower than the sample author intended. The
occlusion-culling pass helped `block_world_1` about 20% and made
`block_world_2` about 12% *worse*.

Fully measurable headlessly, no hardware. It was deliberately parked once in
favour of `sky_strike_1`, so picking it up should be a decision rather than an
assumption.

- [ ] **A3.1** Re-measure both samples on current `main` — the renderer has
      changed since August and the numbers above may no longer hold.
- [ ] **A3.2** Profile before optimising, and write down where the time goes.
- [ ] **A3.3** One optimisation per commit, each with a before/after fps
      number in the commit body.

### A4. Kivy `draw_text` cannot resolve a bare `global.X`

Known, documented, display-only: desktop and HTML5 both special-case
`text='global.team_score'` and resolve it at render time; Kivy emits it as a
literal, so `reseau_2`'s score readout displays the text `global.team_score`.

Blocked on a design question rather than effort — **Kivy has no
global-variable storage at all**, so there is nothing to read. The decision
(build one, or accept and document the limitation) is worth writing down
before any code.

## Track B — manual QA that needs only this Windows box

The `docs/PLATFORM_DISPLAY_CHECKLIST.md` Windows column, plus the items from
the standing backlog that need no other device. **57 boxes are unticked, but
the three automated rows already have recorded evidence** — Windows 5/5 on
2026-08-17, Linux 20/20 on 2026-08-19 — so the genuinely untouched part is
smaller than it looks.

Ordered by value per minute:

- [ ] **B1. Antivirus false-positive scan on a built `.exe`** (~10 min).
      Release-gating and cheap: an unsigned PyInstaller binary is a classic
      false positive, and a teacher who hits one concludes the software is
      malware.
- [ ] **B2. Published GitHub wiki spot-check** (~10 min, browser only).
      Accents rendering as accents, language-switcher banners not 404ing,
      accented-header ToC anchors resolving. Not viewed live since the
      2026-07-29 sweep.
- [ ] **B3. HTML5 exports in a real browser** — Firefox *and* a
      Chromium-based one, from `file://` and from a served directory, plus one
      export carrying the embedded Pyodide runtime, which has never been
      verified end to end in an actual browser.
- [ ] **B4. Play a desktop `.exe`.** The verifier proves an export renders
      frames pixel-identical to the IDE; it cannot tell you whether it feels
      right to hold a key down.
- [ ] **B5. pt / ja / zh visual pass** beyond Preferences and New Project —
      the main window, the Room and Object editors, the Export dialog. One gap
      is already known and is a packaging decision rather than a bug: the
      OK/Cancel button box falls back to Qt's own `qtbase_<lang>.qm`.
- [ ] **B6. Tick what B1–B5 covered** in `PLATFORM_DISPLAY_CHECKLIST.md`, so
      the next pass starts from a real baseline instead of 57 blanks.

## Explicitly NOT now

Recorded so nobody re-derives why these are absent:

- **Everything LAN** — the six manual-QA items in
  `docs/MULTIPLAYER_LAN_V2_PLAN.md` need two machines on a real network.
- **Android on-device** — needs a device; the stub-Kivy harness covers logic,
  not the GL layer. Worth remembering that the four mobile subsystem repairs
  (tiles, keyboard, collision, physics/sub-images) have *never* run on real
  hardware.
- **macOS anything** — no Mac, and PyInstaller cannot cross-compile, so the
  `.app` path is untestable from here.
- **Mobile-browser / touch testing** for HTML5 exports.
- **`docs/WIKI_TUTORIAL_SCREENSHOTS_PLAN.md`** — scoped and ready, but flagged
  "explicit ask only": low value for its effort.
- **Block World crafting** — no plan doc, and by `PROJECT_STATUS.md`'s own
  rule one gets written when it is next in line, not speculatively.
