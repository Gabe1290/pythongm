Bonus: Make It 2.5D

This page is optional. Your maze game is already finished — this is an extra for anyone who wants to try something new. No new maze, no new art for the maze itself: you will look at the exact same maze from the inside, Doom/Wolfenstein style.

Remember Phase 1, where your player showed a different picture for each direction it moved? That was facing direction. A first-person camera needs the exact same idea — which way it is pointing — except instead of picking a picture, it uses that direction to decide what to draw. You already know this pattern; you are about to reuse it.

Turn On the 2.5D View

When created
Enable Raycast View — Field of View 66 Cell Size 32 Render Distance 20
  1. Double-click obj_player to open the Object Editor and click the Blockly tab
  2. Add a new Create event (from Events)
  3. Find Enable Raycast View in the 3D View category and snap it inside
  4. Set Cell Size to 32 — it must match the grid your maze is built on
  5. Leave Camera Object empty — that means "whoever runs this action", i.e. the player
Don't see 3D View in the toolbox? Open File → Project Settings... → Extensions and check 2.5D Raycast View.

Make the Camera Face the Same Way as Your Sprite

Go back to the same 4 arrow-key events from Phase 1 and add one more block to each — Set Facing Angle (from 3D View), using the same angle meaning as a compass: 0 = right, 90 = up, 180 = left, 270 = down.

Keyboard: Right Arrow (held)
Set horizontal speed to 4
Set sprite to spr_player_right
Set Facing Angle 0
Keyboard: Left Arrow (held)
Set horizontal speed to -4
Set sprite to spr_player_left
Set Facing Angle 180
Keyboard: Up Arrow (held)
Set vertical speed to -4
Set sprite to spr_player_up
Set Facing Angle 90
Keyboard: Down Arrow (held)
Set vertical speed to 4
Set sprite to spr_player_down
Set Facing Angle 270
Why not just reuse the sprite? Set Sprite picks a picture; Set Facing Angle picks a number (the angle). The camera needs the number so it can calculate what you would actually see — walls, corridors, everything — from that direction.

The Walls Are Already Solid to the Player

Nothing to add here! Your Collision with obj_wall → Stop movement event from Phase 1 already makes walls block the player — that works exactly the same whether the room is drawn top-down or in first person.

Test Your 2.5D Maze!

Press F5 to play!

  • The room now appears in first person instead of top-down
  • The walls are textured with your own spr_wall picture — you never set a wall texture, each wall just uses its own sprite automatically
  • Turning snaps to face the arrow you are holding, exactly like your sprite did in Phase 1
  • You bump into walls instead of walking through them
  • Coins and the exit still work — they appear floating in the air, facing you, with no changes at all

If Something Looks Wrong

What you seeLikely cause
The normal top-down room, unchangedThe Create event with Enable Raycast View is missing, or 2.5D Raycast View is not checked in File → Project Settings... → Extensions
You walk through wallsobj_wall is not Solid, or Phase 1's Collision with obj_wall event got deleted
Walls look wrong or there are gapsA wall block is off the 32-pixel grid, or Cell Size is not 32
The camera does not turn when you moveA Set Facing Angle block is missing from one of the 4 arrow-key events, or has the wrong number
Turning looks reversed (left shows what should be on the right)Two Set Facing Angle values got swapped — check 0/90/180/270 against the table above

Want More?

Two more 3D View actions exist if you want to keep exploring on your own: Draw Minimap (a little top-down map in the corner of the screen) and Draw DOOM HUD (a classic status bar with health/score). Neither is covered here — try snapping one into your obj_game_controller's Draw event and see what happens!
You just turned a 2D top-down maze into a first-person 3D-style game using the exact same room, the exact same walls, and the exact same facing- direction idea from Phase 1 — just pointed at a camera instead of a sprite.
